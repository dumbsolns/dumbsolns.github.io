Convolutional Neural Networks – Deep Dive

CSE 4237 · PDF pp. 249–342 (X/O example, hyperparameters, parameter calculation) and 599–614 (kernels, sparse connectivity; Goodfellow-style slides). Tags: F24 S24 S25 F23 S23 F22. Parameter counting appeared in F23, S23 and F22 (twice).

1. Why convolutional networks?

PDF pp. 250, 599–614

  • Images are 2-D arrays of pixels. A dense layer on a 64×64×3 image has 12,288 inputs per neuron, huge parameter counts, no use of the fact that nearby pixels are related, and it must relearn a pattern at every location.
  • Convolution slides a small filter (kernel) over the image. A hand-crafted kernel such as [[1,1,1],[1,−8,1],[1,1,1]] detects edges (p. 603). A CNN learns the kernels by backpropagation instead of designing them (p. 607).
  • Sparse connectivity: an output unit depends only on a small patch (e.g. 3×3), not the whole image. Far fewer connections; deeper layers still see larger areas indirectly (p. 611, citing Goodfellow et al. 2016).
  • Parameter sharing: the same kernel weights are reused at every position, so the number of parameters does not depend on image size and a feature is detected anywhere (translation equivariance).
  • A CNN is “a network that uses convolution in place of general matrix multiplication in at least one of its layers”.

2. The X/O walkthrough (how the slides explain it)

PDF pp. 250–324

Task: decide whether a 9×9 pixel image (pixels ±1) shows an X or an O, even if the picture is shifted, scaled or rotated. Comparing pixel by pixel fails; CNNs compare local features.

  1. Features/filters: small patches, e.g. three 3×3 filters (a “\” diagonal, a centre cross, a “/” diagonal).
  2. Convolution (filtering): place the filter on a patch, multiply pixel-by-pixel, add, and divide by the number of pixels (9). A perfect match gives 1.00; e.g. 7/9 = 0.77, 5/9 = 0.55, 3/9 = 0.33, 1/9 = 0.11, −1/9 = −0.11. Doing this at every position creates a feature map (9×9 image with a 3×3 filter → 7×7 map). One map per filter.
  3. ReLU: replace negative values with 0, so only evidence for a feature remains.
  4. Pooling: take the maximum in each 2×2 window, stride 2. The 7×7 map shrinks to 4×4 (the slide includes the partial last window; PyTorch’s default floor would give 3×3). It keeps the strongest response and discards exact position.
  5. Deep stacking: repeat Conv → ReLU → Pool; later layers detect larger and more complex shapes.
  6. Fully connected layer: flatten the final maps; every value votes for X or O with a weight, and the class with the strongest combined vote wins (p. 306 shows votes such as 0.9, 0.65, 0.45, 0.87 … for X and 0.23, 0.63, 0.44 … for O).
  7. Learning (p. 317–321): compare with the right answer: for an X image the network outputs X = 0.92 (target 1) and O = 0.51 (target 0), so X: 1 vs 0.92 → error 0.08; O = 0 vs 0.51 → error 0.49; total error 0.57. Backpropagation + gradient descent adjusts both the filter values and the fully connected weights to reduce this error.
Hyperparameters (“knobs”, p. 324): Convolution: number of features (filters) and size of features. Pooling: window size and stride. Fully connected: number of neurons. (Also stride and padding of the convolution.)

  • Padding “same” for stride 1: P = (F−1)/2, so a 5×5 kernel with P=2 keeps the size (28 → 28). “Valid” = no padding shrinks the map by F−1.
  • Number of output channels = number of filters, whatever the input channels; each filter spans all input channels (hence the C_in factor).
  • Max-, min- and average-pooling all follow the same size formula; only the operation differs.

4. “Pooling always decreases the parameters” – true?

F24 S24 S25 F22

Answer: No, not always. Pooling layers have no parameters. They only shrink the feature maps, so they reduce parameters indirectly: the next fully connected layer gets fewer inputs. If pooling is followed only by conv layers (whose parameter count depends on kernel size and channels, not image size), the total parameters are unchanged.
Numbers from the slide model (28×28 input, two conv layers, 32 filters at the end, FC 512): with two 2×2 poolings the flatten size is 32·7·7 = 1,568 and Linear-10 has 1,568·512 + 512 = 803,328 parameters. Without pooling (stride-1, same padding) the flatten size is 32·28·28 = 25,088 and the same layer has 25,088·512 + 512 = 12,845,568, about 16× more.

S25 (“pooling reduces spatial resolution and discards information, so removing it should improve performance”): misunderstanding.

  • Pooling keeps the strongest activation in each window, which is the signal that a feature is present; the discarded information is mostly the exact position, which the classification does not need. It makes the representation invariant to small shifts and distortions.
  • It enlarges the receptive field quickly: after pooling each later neuron sees a bigger part of the image, so fewer layers are needed.
  • Without pooling, stride-1 convolutions keep full resolution: the activations and the first FC layer become huge (slow training, high memory, many parameters), and the model has enough capacity to memorise the training set, hence it overfits. That matches the symptom in the question.
  • So removing pooling does not mean “losing less information” in a useful way; it keeps more detail, including noise and exact positions. If down-sampling is unwanted, use stride-2 convolutions or global average pooling instead, but something must reduce the resolution.

5. How to count parameters (method)

PDF pp. 333–342

  1. Write the input as C × H × W.
  2. Go layer by layer. For conv/pool compute the new H and W with ⌊(W−F+2P)/S⌋+1 (pool: P=0 and S = window unless stated).
  3. Conv: parameters (F·F·C_in+1)·C_out; channels become C_out.
  4. Flatten: C·H·W = in_features of the first linear layer.
  5. Each linear layer: in·out (+ out if bias). The next layer’s in = previous out.
  6. Sum all; dropout, ReLU, pooling and flatten add 0.
Slide model (p. 338, 28×28 input): Conv2d(1→16, 5×5, p2): (25·1+1)·16 = 416; ReLU/Pool: 16×14×14; Conv2d(16→32): (25·16+1)·32 = 12,832; Pool: 32×7×7 = 1,568; Linear 1568→512: 803,328; Linear 512→128: 65,664; Linear 128→10: 1,290. Total 883,530.
Slide MLP example (p. 340): input 1024 → FCwB(256): 1024·256+256 = 262,400 → Dropout → FC(128): 256·128 = 32,768 → tanh → Maxpool(3): ⌊(128−3)/3⌋+1 = 42 → FC(3): 42·3 = 126. Total 295,294.

8. Rule of thumb: when to use a CNN

PDF pp. 326–332 · F24 S24 F22

  • CNNs work on any 2-D (or 3-D) data where things closer together are more closely related than things far apart (p. 326): images, sound as a spectrogram (time steps × frequency bands, p. 328), also text as a position × embedding grid.
  • Rule of thumb (p. 332): if your data is just as useful after swapping any of your columns with each other, you cannot use a CNN. Tabular data (p. 331: name, id, e-mail, phone columns) fails the test; images fail it too if you shuffle pixels.
  • Limitation (p. 330): CNNs capture only local spatial patterns. If the data cannot be made to look like an image (no neighbourhood structure), CNNs are less useful.

9. Normalization in CNNs

PDF pp. 709, 714 · F24 S24 F22

  • Input standardization / normalization (pp. 709, 714): rescale pixels before the network, e.g. divide by 255 to [0,1], then subtract the mean and divide by the standard deviation per channel: x′ = (x − μ)/σ. The slide uses Normalize((0.5,0.5,0.5), (0.5,0.5,0.5)) for RGB, which maps [0,1] to [−1,1]. Zero-centred inputs of similar scale make gradient descent converge faster and more stably.
  • Batch normalization (BatchNorm and variants, p. 709): inside the network, after a conv layer (before ReLU), normalise each channel over the mini-batch: x̂ = (x−μB)/√(σ²B+ε), then y = γx̂ + β with learnable γ, β. It stabilises training, allows larger learning rates and acts as a mild regulariser. Variants: layer, instance, group normalization.
  • Normalization layers add parameters only γ and β per channel (2·C).

10. Exam kit

Model answer, pooling question (6 marks)
False as stated. Pooling has no learnable parameters; it only down-samples feature maps, which indirectly lowers the parameters of later fully connected layers (example: 803,328 vs 12.8 M). If only conv layers follow, parameters are unchanged. Pooling also gives translation invariance and a larger receptive field, so removing it makes the model slower and more prone to overfitting. Rule of thumb: use a CNN when neighbouring values are related; if shuffling columns does not hurt, do not use one.

Traps

  • Use floor on every size; compute height and width separately.
  • The first Linear layer’s in_features = C·H·W after the last pool.
  • Check the bias flag on each layer (FCwB vs FC; bias=False).
  • Conv parameters depend on the input channels of that layer, not the image size.
  • Min/max/avg pooling: no parameters, same size formula; dropout/ReLU: no parameters.
