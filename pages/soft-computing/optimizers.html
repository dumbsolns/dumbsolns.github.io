Optimizers: SGD, Momentum, Nesterov, AdaGrad, RMSProp, Adam – Deep Dive

CSE 4237 · PDF pp. 72–79 and 638–648 (gradient descent basics), 615–637 (SGD problems, momentum, Nesterov, adaptive learning rates, Adam; slides after Mitesh Khapra’s CS7015). Tags: S25 F24 S24 S23 F22. An optimizer question appeared in every exam.

1. Why optimizers? Gradient descent recap

PDF pp. 72–79, 638–648 · F22: importance of an optimizer / of gradient descent

  • Training a network means finding the parameters that minimise the cost J(w, b). Brute-force search is hopeless (2 weights × 1000 values = 10⁶ evaluations, growing exponentially with every weight), so we follow the gradient.
  • Gradient descent: w := w − α·∂J/∂w, b := b − α·∂J/∂b (α = learning rate, p. 643). The slope (derivative) tells which way is uphill: positive slope → decrease w, negative → increase w (p. 642). For logistic regression J is convex, so any start reaches the global optimum (p. 640).
  • Derivative intuition (pp. 644–646): slope of the tangent line; for f(a) = 3a the slope is 3; for f(x) = x² the derivative is 2x. For several parameters we use partial derivatives (p. 648).
  • Deep networks are non-convex: a function has a global minimum, local minima/maxima (p. 639). Second-derivative test (p. 647): at f′(c) = 0, f″(c) > 0 → local minimum; f″(c) < 0 → local maximum; f″(c) = 0 → inconclusive (saddle/flat).
  • Gradient size matters (pp. 616–617): since the update is proportional to the gradient, steps are large on steep parts and tiny on gentle slopes, so progress slows down on plateaus.
Importance of an optimizer (3 marks, F22): the optimizer is the algorithm that updates the weights using the gradients of the loss. Its choice decides how fast training converges, whether it escapes poor local minima/plateaus, and how stable and accurate the final model is. Plain GD is slow and sensitive to the learning rate; momentum and adaptive optimizers (RMSProp, Adam) fix this.

2. Batch, stochastic and mini-batch gradient descent

PDF pp. 95–101, 618–619

  • Batch GD: gradient over all m examples per update: exact but slow for large data. SGD: one random example per update: cheap but noisy. Mini-batch: a few dozen to a few hundred examples: the usual compromise (vectorised, smoother than SGD).
  • Problems with SGD (pp. 618–619): noisy updates and frequent fluctuations of the loss; slow convergence; sensitive to the learning rate (too high diverges, too low is slow); may get stuck in local minima or saddle regions; less efficient than batch GD on small datasets; needs extra techniques (momentum, learning-rate decay, adaptive optimizers); overfits noisy patterns without regularization.
  • The ravine problem (p. 618): if the loss changes quickly in one direction and slowly in another (elongated contours), plain gradient descent makes very slow progress along the shallow dimension and jitters along the steep dimension. Momentum and adaptive learning rates were invented for this.

3. Momentum

PDF pp. 620–625 · F24: “examine SGD and how momentum improves it” (6 marks)

Intuition (p. 622): if I am repeatedly asked to move in the same direction I should gain confidence and take bigger steps, like a ball gaining speed rolling down a slope. So use the history of updates in addition to the current gradient.

updatet = γ·updatet−1 + η·∇wt  ·  wt+1 = wt − updatet   (γ ≈ 0.9, update₀ = 0)

Unrolling (p. 623): updatet = γt−1η∇w₁ + γt−2η∇w₂ + … + η∇wt: an exponentially weighted sum of all past gradients, recent ones weighing most.

Why it helps (numbers, η = 0.1, γ = 0.9). Consistent gradient g = 1 each step: updates 0.1, 0.19, 0.271, 0.344, … → η/(1−γ) = 1.0, i.e. up to 10× faster than plain SGD (0.1 per step) on a gentle but steady slope. Oscillating gradient +1, −1, +1, −1: updates 0.1, −0.01, 0.091, −0.018, … → the zig-zag cancels (steps shrink from 0.1 to ~0.01–0.09), so the jitter along the steep direction is damped while the steady direction accelerates.
  • Observations (pp. 624–625): momentum carries the update through gentle regions (large steps because history accumulates); but it can overshoot: it oscillates in and out of the minimum valley, with many U-turns before converging. Even so it converges much faster than vanilla GD: slide example, after 100 iterations momentum reaches error 0.00001 while vanilla GD is still at 0.36.

4. Nesterov accelerated gradient (NAG)

PDF pp. 626–630

Intuition (“look before you leap”): we are going to move by at least γ·updatet−1 anyway, so compute the gradient at that partially updated (look-ahead) point instead of at the current point.

wlook-ahead = wt − γ·updatet−1
updatet = γ·updatet−1 + η·∇wlook-ahead
wt+1 = wt − updatet
  • Picture (p. 629): first make a big jump in the direction of the previous accumulated gradient (brown), then measure the gradient where you end up and make a correction (red); the sum is the accumulated update (green). Standard momentum (blue) takes the gradient at the start, so it overshoots further.
  • Observation (p. 630): looking ahead lets NAG correct its course quicker than momentum, so oscillations are smaller and the chance of escaping the minimum valley is smaller.

5. AdaGrad

PDF pp. 631–632 · S24 F22: RMSProp vs AdaGrad

Idea: adapt the learning rate per parameter: decay it in proportion to the parameter’s update history (more updates ⇒ more decay). Parameters of rare/sparse features keep large steps; frequently updated ones get small steps.

vt = vt−1 + (∇wt)²  ·  wt+1 = wt − η/√(vt + ε) · ∇wt   (and the same for b)

Weakness (p. 633): v only grows (it is a cumulative sum), so the effective learning rate decays very aggressively; after a while even the useful parameters get tiny updates and learning stalls before convergence.

6. RMSProp

PDF p. 633

Idea: to avoid AdaGrad’s rapid growth of the denominator, decay the denominator: keep an exponentially weighted moving average of the squared gradients instead of the full sum.

vt = β·vt−1 + (1−β)·(∇wt)²  ·  wt+1 = wt − η/√(vt + ε) · ∇wt   (β ≈ 0.9)

7. Adam (adaptive moment estimation)

PDF pp. 634–635 · S25 S23 F22: write the algorithm

Idea (p. 634): do everything RMSProp does to solve the decay problem of AdaGrad, plus use a cumulative history of the gradients (momentum). Defaults β₁ = 0.9, β₂ = 0.999, ε = 10⁻⁸.

mt = β₁·mt−1 + (1−β₁)·∇wt (velocity / first moment: history of gradients)
vt = β₂·vt−1 + (1−β₂)·(∇wt)² (gradient accumulation / second moment)
m̂t = mt/(1−β₁t),   v̂t = vt/(1−β₂t) (bias correction)
wt+1 = wt − η/√(v̂t + ε) · m̂t  (many texts write √v̂t + ε; numerically almost identical)
  • Bias correction: m₀ = v₀ = 0, so the first estimates are biased towards zero (especially v with β₂ = 0.999). Dividing by (1 − βᵗ) removes this; the correction fades as t grows.
  • Step-size property: the step is about η·m̂/√v̂, so its size is roughly η whatever the gradient scale.
First Adam step, g = 2, η = 0.001: m₁ = 0.1·2 = 0.2; v₁ = 0.001·4 = 0.004; m̂₁ = 0.2/0.1 = 2; v̂₁ = 0.004/0.001 = 4; step = 0.001·2/√4 = 0.001 (= η). Without bias correction the step would be 0.001·0.2/√0.004 = 0.0032.

Which to use in practice (p. 635): Adam is more or less the default choice now (η = 0.001 or 0.0001 works well for sequence tasks); SGD with momentum (classical or Nesterov) with a simple annealing schedule also works well and is often reported as best; recent work shows Adam may fail to converge in some cases.

10. Exam kit

“Examine SGD and explain how momentum improves it” (6 marks) F24
SGD updates with one (or a mini-batch of) example(s): w := w − η∇w. It is cheap but noisy, zig-zags across steep directions and crawls along gentle ones (ravine problem), and is sensitive to η. Momentum adds a velocity: updatet = γ·updatet−1 + η∇wt, wt+1 = wt − updatet, an exponential average of past gradients. Consistent gradient directions accumulate (faster, up to η/(1−γ)), oscillating ones cancel (smoother), and it helps cross plateaus and shallow local minima. Cost: overshoot/oscillation (NAG reduces this).
“Which SGD variant with adaptive learning rate uses interim updates? Write the gradient accumulation and velocity update steps” (6 marks) S25
Adam: velocity (first moment) mt = β₁mt−1 + (1−β₁)gt; gradient accumulation (second moment) vt = β₂vt−1 + (1−β₂)gt²; bias-corrected interim estimates m̂t = mt/(1−β₁ᵗ), v̂t = vt/(1−β₂ᵗ); update w = w − η m̂t/√(v̂t + ε). (If “interim” means Nesterov’s look-ahead point w − γ·updatet−1, note that NAG is not adaptive; the adaptive variant that has both velocity and accumulation is Adam.)
“RMSProp vs AdaGrad” (4–7 marks) S24 F22 → §5–6 equations and table. “RMSProp vs Adam” (7 marks) S23: RMSProp = EMA of squared gradients only (v), update η g/√(v+ε); Adam adds the first-moment (momentum) m, and bias-corrects both m and v, update η m̂/√(v̂+ε). “Importance of gradient descent; write Adam” (6 marks) F22 → §1 and §7.

Traps

  • AdaGrad accumulates a sum; RMSProp/Adam use (1−β)-weighted averages.
  • Adam bias correction divides by (1 − βᵗ) with t the step number (β₁ᵗ, β₂ᵗ are powers).
  • NAG evaluates the gradient at w − γ·updatet−1, not at wt.
  • All updates subtract (w := w − …); momentum’s “update” already includes η.
  • RMSProp and AdaGrad have no momentum term; Adam = RMSProp + momentum + bias correction.

Likely short questions

  • Local vs global minimum; second-derivative test.
