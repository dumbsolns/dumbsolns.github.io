Generalization, Overfitting & Regularization – Deep Dive

CSE 4237 · PDF pp. 559–598 (pattern recognition example, overfitting, bias-variance, model evaluation, cross-validation) and pp. 702–746 (Raschka STAT 453, Lecture 10: regularization methods). Tags: S25 S24 and the 2022–23 papers (bias, overfitting, cross-validation, L2, dropout, early stopping).

1. What is generalization?

PDF pp. 571–576, 582

The purpose of machine learning is not to learn the given data as exactly as possible, but to predict unknown data as accurately as possible from what was learned (p. 575). The ability to do well on unseen data is generalization.

  • Polynomial curve fitting example (pp. 571–576): ten points are fitted by polynomials of order M = 0, 1, 3, 9. As the order (model complexity) increases, the curve fits the training points more exactly; at M = 9 the training error is zero (the curve goes through every point), yet the curve oscillates wildly between points and predicts new data badly. “Least training error” therefore does not mean “best model”.
  • Training vs test error (p. 582): training error keeps falling with M and reaches 0 at M = 9, while the test error falls, stays flat, then jumps up for large M.

2. Pattern-recognition example: sorting fish

PDF pp. 559–570 (after Duda, Hart & Stork)

  • Pipeline: capture image → isolate fish → take measurements (features) → make the decision. Sensing problems: lighting, position of fish on the belt, camera noise.
  • One feature (pp. 560–563): use length with a threshold l*. Sea bass are longer on average, but the histograms overlap, so no threshold gives perfect decisions. Try lightness instead: better separation, still not perfect.
  • Cost of errors (p. 564): misclassifying salmon as sea bass and the reverse have different costs (customers object loudly to sea bass in salmon cans), so the threshold should reflect cost, not only accuracy.
  • Two features (pp. 565–566): lightness x₁ and width x₂ give a feature vector x = (x₁, x₂) and a decision boundary in the feature plane.
  • More features always better? No (p. 567, 570): avoid unreliable features; correlated features add nothing (redundant); there are measurement costs and noise; too many features lead to the curse of dimensionality (data becomes sparse, models overfit).
  • Boundaries (pp. 568–569): a very complex boundary classifies every training fish correctly but “how can we predict how well we generalise to unknown samples?”; a smoother boundary may make a few training errors but generalises better. This is the tradeoff between complexity of decision rules and performance on unknown samples.

  • Underfitting (p. 577): the model makes a strong assumption (e.g. price varies linearly with size), so it cannot fit even the training data (poor fit, high bias).
  • Overfitting: the hypothesis space is too large; with too little data the model fits noise and has ~0 training error but poor performance on new data (high variance).
  • Complexity curve (p. 579): as model complexity rises, training error always falls; test error is U-shaped: high bias on the left (underfitting), high variance on the right (overfitting), with a “good model complexity” at the minimum of the test curve.
  • What makes overfitting more likely: (1) not enough training examples (small dataset); (2) too many features; (3) a model/hypothesis function that is too complex for the problem.
  • Addressing overfitting (p. 580): (1) hyperparameter tuning: compute the generalization error of models of different complexity and keep the best; (2) reduce the number of features; (3) ensemble methods (e.g. random forest for decision trees); (4) regularization: keep all features but reduce the magnitude of the parameters θj (works well with many features that each contribute a little).

5. Bias and variance

PDF pp. 583–587 · S25 S24 F22

  • Bias = the difference between the model’s average prediction and the true value we try to predict. A model that is too simple fails to capture the patterns in the data (a fundamental limitation): high bias = underfitting. Low-complexity models tend to have high bias.
  • Variance = how much the predictions change if a different training dataset is used. A model that is too flexible fits small fluctuations, memorises rather than learns general patterns: high variance = overfitting. High-complexity models tend to have high variance.
  • Bullseye picture (p. 586): the target is the true function, the darts are models learned from different datasets. High bias = darts far from the centre; high variance = darts scattered. Four combinations: low/low (ideal), high bias/low variance, low bias/high variance, high/high. (Same idea as accuracy vs precision on p. 587.)
  • Tradeoff: increasing complexity lowers bias but raises variance; the goal is the complexity that minimises total test error. In formula (standard result, beyond the slides): Expected error = Bias² + Variance + irreducible noise.

S25 case: a deep ANN reaches 98% training but 62% test accuracy, a gap of 36 points. Training error is tiny (2%), test error is large (38%): low bias, high variance, i.e. overfitting. A deep ANN has huge capacity relative to the data, so it memorises training examples.

6. Model evaluation: training, validation and test sets

PDF pp. 581, 588–591, 716

  • Different models (or hyperparameter values) must be compared. Divide the data into a training set and a test set that do not overlap and are as independent as possible; build several models on the training set, evaluate each on the test set, choose the model with the best test performance (pp. 588–589).
  • Test set size: about 20–30% of the data (slide: “50~30%”). Advantage: simple and easy. Disadvantage: the test data is not used for building the model (waste of data), and because the split is random the result can differ a lot from split to split (split 1 gives bad performance, split 2 good, p. 591).
  • Three-way split (p. 716): training set (fit the weights), validation set (tune hyperparameters, choose the model, decide when to stop), test set used only once at the end for an unbiased estimate of generalization performance. If you tune on the test set, your estimate is optimistic.

7. Cross-validation

PDF pp. 592–598 · S24: bias-variance and the role of cross-validation

  1. Split the data into k folds of equal size that do not overlap.
  2. Repeat k times: use k−1 folds as the training set and the remaining fold as the test (validation) set (a different fold each time).
  3. Compute the performance on each held-out fold and take the average; choose the model/hyperparameters with the best average performance, then retrain on all data.

4-fold example (pp. 593–597): Set I trains on folds 1, 2, 3 and tests on fold 4; Set II trains on 4, 1, 2 and tests on 3; Set III trains on 3, 4, 1 and tests on 2; Set IV trains on 2, 3, 4 and tests on 1. Model 1, 2, …, n are each scored on the four test folds, then the model with the best average of the 4 results is chosen.

  • Advantages (p. 598): less dependent on how the data is split; every data point is in a test set exactly once and in a training set k−1 times; the variance of the estimate is reduced as k increases.
  • Disadvantage: time: k trainings instead of one.
  • Role for soft-computing models: small datasets make a single split unreliable; CV gives a stable estimate of generalization for comparing fuzzy/neural models and tuning hyperparameters (number of rules, hidden units, λ, learning rate) without touching the final test set.
Numbers: accuracies over 4 folds — Model A: 0.82, 0.78, 0.80, 0.84 → mean 0.81; Model B: 0.88, 0.70, 0.90, 0.72 → mean 0.80 but with a much larger spread. A single lucky split (folds 1 and 3) would favour B; the average (and the spread) shows A is as good and more stable.

8. Regularization: the big picture

PDF pp. 703–715

Goal: reduce overfitting, usually by reducing model capacity and/or reducing the variance of the predictions. Regularization in deep learning means adding information or changing the objective function to prevent overfitting (p. 704). Common techniques for deep networks (p. 705): early stopping, L1/L2 norm penalties, dropout.

Improving generalization (p. 709) is wider: collecting more data, data augmentation, label smoothing, leveraging unlabeled or related data (semi-/self-supervised, transfer learning), weight initialization, activation functions, architecture (residual layers), input standardization, knowledge distillation.

  • More data (p. 711): often the best way to reduce overfitting. The learning curves of softmax classifiers on MNIST show the gap between training and test error shrinking as the training set grows (with a small set the model picks up noise).
  • Data augmentation (pp. 712–714): create new training examples by random label-preserving transformations (flip, crop, rotate, colour jitter) with TorchVision; remember to normalise (e.g. mean and std (0.5, 0.5, 0.5) for RGB).
  • Early stopping (pp. 716–717): split into training/validation/test; watch the training/validation gap during training and stop at the “right” epoch where the validation accuracy is best (before the gap grows). The slides note it is not very common anymore.

9. L1 and L2 regularization (norm penalties)

PDF pp. 719–726 · S25 S24: L2

  • L2 = Ridge regression / Tikhonov; L1 = LASSO. Both are “weight shrinkage” or a “penalty against complexity”.
  • L2 cost for a linear model: Cost = (1/n) Σ L(y⁽ⁱ⁾, ŷ⁽ⁱ⁾) + (λ/n) Σj wj². For a multilayer network: (1/n)Σ L + (λ/n) Σl ‖w(l)‖F² (Frobenius norm of each layer’s weight matrix; biases are not penalised) (p. 723).
  • L1: Cost = (1/n)ΣL + (λ/n) Σ|wj|.
Gradient and update (weight decay), p. 724: ∂Cost/∂w = ∂L/∂w + (2λ/n)·w, so w := w − η·∂L/∂w − (2ηλ/n)·w = (1 − 2ηλ/n)·w − η·∂L/∂w. Each step first shrinks the weights by the factor (1 − 2ηλ/n), then applies the usual gradient step. In PyTorch: weight_decay=LAMBDA in the optimizer (p. 726) or add the sum of squared weights to the loss (p. 725).
w = 2.0, η = 0.1, λ = 0.5, n = 10 ⇒ 2ηλ/n = 0.01; with zero data gradient the new w = 2.0·0.99 = 1.98; repeated, weights decay towards 0 unless the data gradient pushes back.
  • Geometric interpretation (p. 721): minimise the loss subject to a penalty region: the L2 region is a circle/sphere, so the solution is a small-norm vector with all weights shrunk but non-zero; the L1 region is a diamond with corners on the axes, so the solution often lands on a corner, making some weights exactly zero (sparse, built-in feature selection).
  • Effect on the decision boundary (p. 722): a larger λ gives a smoother, simpler boundary (less variance, more bias); λ too large underfits, λ = 0 is no regularization.
  • λ is a hyperparameter chosen with a validation set or cross-validation.

10. Dropout

PDF pp. 727–746 · S25 F24 (dropout), S24

  • Main idea (p. 729–731): during training, each hidden node is dropped (its activation set to 0) with probability p. Practical implementation by Bernoulli sampling: draw v ~ Uniform[0,1] for each unit; mask mi = 0 if vi < p else 1, and multiply the activations by the mask. A new random sub-network is used for every mini-batch.
  • Co-adaptation interpretation (p. 733): the network cannot rely on particular connections or units, so it must use many connections; the weights become more spread out (smaller, similar to the effect of L2).
  • Ensemble interpretation (pp. 735–737): each mini-batch trains a “different model”; with h hidden units there are M = 2h possible sub-networks, trained with weight sharing (itself a regularizer). At test time averaging all models is too expensive; instead use the full network with predictions scaled by a factor (1 − p), which approximates the geometric mean of the ensemble.
  • Inverted dropout (p. 739): frameworks apply the scaling during training instead: divide the surviving activations by (1 − p), so inference needs no change and is cheaper when the model is used a lot.
  • Practical tips (p. 741–743): in PyTorch call model.train() for training and model.eval() for inference (dropout must be off at test time). Do not use dropout if the model does not overfit; if it does not, increase capacity until it overfits and then add dropout, which lets you use a larger network.
  • DropConnect (pp. 744–745): drops individual weights rather than whole nodes, a generalization of dropout with more possibilities; less popular and works less well in practice.
Numbers: activations a = [0.8, 0.2, 0.5, 0.9], p = 0.5, random draws v = [0.7, 0.3, 0.9, 0.1] ⇒ mask [1, 0, 1, 0] ⇒ [0.8, 0, 0.5, 0]. Inverted dropout divides by 1 − p = 0.5 ⇒ [1.6, 0, 1.0, 0]; the expected value of each activation is unchanged. At inference: no mask, no scaling.

11. Exam kit

“98% train, 62% test: analyse with bias-variance and compare L2, dropout and early stopping; which first?” (6 marks) S25
Cause: low bias but high variance: the deep ANN has far more capacity than the data supports and memorised the training set (overfitting; gap 36 points). L2: adds (λ/n)Σ‖w‖² so weights shrink, smoother function, lower variance; needs λ tuning; cheap. Dropout: random nodes dropped each mini-batch, prevents co-adaptation, acts like an ensemble of 2h sub-networks; strong for deep nets; slower convergence. Early stopping: stop when validation accuracy stops improving; essentially free, needs a validation set, limits training rather than changing the model. First: early stopping (and more data/augmentation if cheap), because it needs no change to the architecture or loss and costs nothing; then add L2 as a baseline and dropout if the gap persists. (Justify your choice.)
“What is the bias-variance tradeoff? Role of cross-validation in evaluating soft-computing models” (3 marks) S24
Bias = error from overly simple assumptions (underfitting); variance = sensitivity to the training set (overfitting). Increasing complexity lowers bias and raises variance, so we seek the complexity with minimum test error. k-fold cross-validation rotates the held-out fold, averages the k scores, gives a reliable estimate of generalization and lets us choose models and hyperparameters without wasting data or depending on one lucky split.

Traps

  • Training error always falls as complexity rises; only the test error is U-shaped.
  • Never tune on the test set; it is used once at the end.
  • Biases are not regularized; L2 shrinks weights, L1 produces exact zeros.
  • Dropout is only active during training; inverted dropout divides by (1 − p).
  • Early stopping needs a validation set, not the test set.
  • Regularization increases bias slightly to reduce variance a lot.

Likely questions
