What data mining is, and the KDD steps

Data mining is extracting interesting patterns or knowledge from large amounts of data. KDD (Knowledge Discovery from Data) is the full process; data mining is one step of it.

  1. Data cleaning: remove noise and inconsistent data.
  2. Data integration: combine multiple sources.
  3. Data selection: retrieve only data relevant to the analysis.
  4. Data transformation: consolidate into forms suitable for mining (summary or aggregation).
  5. Data mining: apply intelligent methods to extract patterns.
  6. Pattern evaluation: identify the truly interesting patterns.
  7. Knowledge presentation: visualization and reporting.

Steps 1–4 together are data preprocessing.

Notes check: your notes list the steps as “sequential”. The book calls KDD an iterative sequence (you can loop back). Data mining can mean one step or the whole process; the book adopts the broad view.

Kinds of data and kinds of patterns
  • Data kinds: database data, data warehouses, transactional data (plus streams, graphs, text, multimedia and so on).
  • Characterization: summarizes the general features of a target class. Discrimination: compares target class against contrasting classes.
  • Frequent patterns: frequent itemsets (items bought together), frequent subsequences (ordered across transactions), frequent substructures.
  • Association: rules such as A ⇒ B with support and confidence.
  • Classification and regression: predict a class label or numeric value. Training data has the class attribute value; test data does not.
  • Clustering: group unlabeled objects. Outlier analysis: find extreme or unusual objects.

Book: §1.3 “What Kinds of Data Can Be Mined?”, §1.4 “What Kinds of Patterns Can Be Mined?”. Notes: 24/06/26, 25/06/26.

Interestingness, technologies, applications and issues

A pattern is interesting if it is understandable, valid on new data, potentially useful and novel. Objective measures: support, confidence, accuracy, coverage. Subjective measures: unexpected or actionable. Interestingness measures and constraints can also prune the search during mining, not only rank results afterwards.

  • Technologies: statistics, machine learning (supervised ≈ classification, unsupervised ≈ clustering, semi-supervised, active learning), database and warehouse systems, information retrieval; also pattern recognition, visualization, algorithms, high-performance computing.
  • Applications: business intelligence (data mining is its core) and Web search engines (huge data, online models, rare queries).
  • Major issues: mining methodology, user interaction, efficiency and scalability, diversity of data types, data mining and society (privacy, invisible data mining).
  • Descriptive vs predictive: characterization, discrimination, frequent patterns and clustering describe; classification and regression predict.

Data objects and attribute types
  • Data object: an entity (row, sample, instance). Attribute: a characteristic (column, feature, dimension). A set of attributes describing an object is an attribute vector.
  • Nominal: names or categories with no order (colour, code).
  • Binary: two values. Symmetric if both are equally important; asymmetric if one outcome matters more (for example a positive test).
  • Ordinal: ranked values where the gaps are unknown (low, medium, high).
  • Numeric: interval-scaled has no true zero (temperature in °C, 0 does not mean “nothing”). Ratio-scaled has a true zero (height, weight, count).
  • Discrete means a finite or countable set of values. Continuous means real numbers.

Central tendency and skew
Mean x̄ = Σx / N Weighted x̄ = Σ wᵢxᵢ / Σ wᵢ Median (grouped) = L + ((N/2 − (Σfreq)ₗ) / freq_median) × width Empirical (moderately skewed): mean − mode ≈ 3 × (mean − median)

L is the lower bound of the median interval, (Σfreq)ₗ is the cumulative frequency before it, width is the interval width. Median for even N: average the two middle values after sorting.

  • Symmetric: mean = median = mode.
  • Positively skewed (long right tail): mode < median < mean.
  • Negatively skewed (long left tail): mean < median < mode.
  • The mean is pulled toward outliers; the median is robust.

Dispersion: quantiles, IQR, boxplot, variance
  • Range = max − min. Quartiles Q1, Q2 (median), Q3 are the 25th, 50th and 75th percentiles. IQR = Q3 − Q1.
  • Outlier rule: x ≤ Q1 − 1.5·IQR (low) or x ≥ Q3 + 1.5·IQR (high).
  • Five-number summary: min, Q1, median, Q3, max. A boxplot draws it, with outliers as separate points.
Variance σ² = (1/N) Σ(xᵢ − x̄)² = (1/N) Σxᵢ² − x̄² Std dev σ = √σ² (use N−1 for a sample, to avoid bias)
Quartile method. Your notes use the median of the two halves. The book’s Example 2.10 takes the 3rd, 6th and 9th values for 12 data points (Q1 = 47, Q3 = 63), and spreadsheets interpolate. For the 12-value past-paper data this changes the outliers: S25 1g gives −95, 255, 590 with halves, but −95, −40, 120, 255, 590 with the book’s style. Name your method in the answer. Boxplot whiskers stop at the most extreme points within 1.5 × IQR; points beyond are plotted separately.

Similarity and dissimilarity measures

Data matrix is objects × attributes. Dissimilarity matrix is objects × objects, with d(i,i) = 0 on the diagonal and symmetric entries, so only the lower triangle is stored.

TypeDissimilarity d(i,j)
Nominal(p − m) / p, where p is the number of attributes and m the number of matches
Symmetric binary(r + s) / (q + r + s + t)
Asymmetric binary(r + s) / (q + r + s), ignoring 0-0 matches (t)
OrdinalReplace by rank r, normalize z = (r − 1)/(M − 1), then use a numeric distance
NumericEuclidean: √Σ(xᵢ−yᵢ)². Manhattan: Σ|xᵢ−yᵢ|. Minkowski: (Σ|xᵢ−yᵢ|ʰ)^(1/h). Supremum: max|xᵢ−yᵢ|

In the binary contingency table: q = both 1, r = i has 1 and j has 0, s = i has 0 and j has 1, t = both 0. Minkowski with h = 1 is Manhattan and h = 2 is Euclidean. Mixed attribute types: compute each attribute’s distance in [0,1] and average. Cosine similarity suits sparse text vectors.

Exam tip: the notes’ nominal example with a fourth attribute (black, black, white, white) gives d(1,2) = (2 − 1)/2 = 0.5.

Other books: what they add
  • Tan et al. use four scale types: nominal (any one-to-one mapping), ordinal (order-preserving), interval (x′ = a·x + b) and ratio (x′ = a·x). Han lists binary separately and splits numeric into interval and ratio. The scale decides which statistics are meaningful.
  • Binary similarity (Tan): simple matching coefficient SMC = (f₁₁ + f₀₀)/(all attributes) and Jaccard J = f₁₁/(f₀₁ + f₁₀ + f₁₁). In Han’s table, q = f₁₁, r = f₁₀, s = f₀₁, t = f₀₀, so symmetric d = 1 − SMC and asymmetric d = 1 − Jaccard.
  • Correlation is the cosine of the mean-centred vectors (Tan). Zaki & Meira reach correlation from covariance in the same way.
  • Mahalanobis distance (Tan) uses the covariance matrix to account for correlated attributes; Han stops at Minkowski.

Data quality and major tasks

Quality dimensions: accuracy, completeness (no missing values), consistency (same format and meaning), timeliness, believability, interpretability.

Major tasks: cleaning (fill missing values, smooth noise, remove outliers, resolve inconsistency), integration (merge sources), reduction (dimensionality and numerosity), transformation and discretization.

Book: §3.1 “Data Preprocessing: An Overview”. Notes: 16/07/26.

Go deeper: §3.1 Overview →

Data cleaning: missing and noisy data

Missing values:

  1. Ignore the tuple (poor unless many attributes are missing).
  2. Fill in manually (infeasible at scale).
  3. Use a global constant such as “Unknown”.
  4. Use the attribute mean or median.
  5. Use the mean or median of tuples in the same class (smarter).
  6. Use the most probable value (regression, Bayesian, decision tree).

Methods 3 to 6 can bias the data.

Noisy data: smooth by binning (sort, split into equal-frequency bins, replace by bin mean, median or boundaries), regression (fit a function), or outlier analysis (clustering).

Data integration: redundancy, χ² and correlation

Strongly correlated attributes are redundant, so one can be dropped. Also handle entity identification and conflicting values across sources.

Nominal: χ² test.

eᵢⱼ = count(A=aᵢ) × count(B=bⱼ) / n χ² = Σ (oᵢⱼ − eᵢⱼ)² / eᵢⱼ degrees of freedom = (rows − 1)(cols − 1)

If χ² exceeds the table value at the given significance level, reject the null hypothesis (independence), so the attributes are correlated. Larger χ² means stronger evidence.

Numeric: Pearson correlation.

r = Σ(aᵢ − Ā)(bᵢ − B̄) / (n σA σB), −1 ≤ r ≤ 1 Cov(A,B) = E[(A − Ā)(B − B̄)]

r > 0 positive, r < 0 negative, r = 0 no linear correlation. Covariance gives only the sign of the relationship; r also gives its strength. Correlation does not imply causation.

Book: §3.3 “Data Integration”, §3.3.2 “Redundancy and Correlation Analysis” (χ² for nominal data, correlation coefficient and covariance for numeric data). Notes: 22/07/26, 23/07/26.

Data reduction: DWT, PCA, attribute subset selection

Dimensionality reduction uses data compression (DWT, PCA), attribute subset selection, or attribute construction. Numerosity reduction uses parametric models (regression) or non-parametric ones (histograms, clustering, sampling).

DWT (discrete wavelet transform): lossy. Length must be a power of 2 (pad with 0s). Repeatedly take pair averages (low pass) and half-differences (high pass) until one value is left; keep the coarse value and the details.

[8 12 16 40 45 60 80 100] Avg₁ [10 28 52.5 90] Diff₁ [−2 −12 −7.5 −10] Avg₂ [19 71.25] Diff₂ [−9 −18.75] Avg₃ [45.125] Diff₃ [−26.125] Result [45.125 −26.125 −9 −18.75 −2 −12 −7.5 −10]

PCA: find orthogonal principal components that capture the most variance; keep the first few.

  1. Normalize (z-score).
  2. Build the covariance matrix C.
  3. Solve |C − λI| = 0 for eigenvalues (they measure variance).
  4. Find eigenvectors (the loadings); sort by eigenvalue; PC1 has the largest.

Notes’ example (hours studied vs marks, cov ≈ 1): C = [[1,1],[1,1]], λ = 2 and 0, PC1 = [1/√2, 1/√2], so one component carries all the variance.

Attribute subset selection removes irrelevant or redundant attributes:

  • Stepwise forward: start with an empty set, repeatedly add the attribute that improves the measure most, stop when no gain.
  • Stepwise backward: start with all, remove the worst repeatedly.
  • Combination: add the best and remove the worst at each step.
  • Decision tree induction: attributes that appear in the tree are kept.

Sampling: SRSWOR (without replacement), SRSWR (with replacement), cluster sample (pick whole groups; some classes may be lost), stratified sample (SRS within each stratum in proportion to the original).

Checks: (1) the class DWT uses average and half-difference, while the book’s Haar uses 1/√2 scaling, so state which one you use. (2) In your PCA example the covariance 0.992 comes from rounded z-values; the exact value is 1, so λ = 2 and 0. (3) A 2 × 2 correlation matrix [[1, r],[r, 1]] has λ = 1 ± r.

Other books: what they add

What a data warehouse is, and OLTP vs OLAP

A data warehouse is a repository of information from multiple sources, stored under a unified schema, usually at one site. It is not just a big database. Its four properties:

  • Subject-oriented: organized around subjects such as customer or sales, not applications.
  • Integrated: built from several databases and files, with cleaning to ensure consistency.
  • Time-variant: holds a long history (5–10 years), each record has a time element.
  • Nonvolatile: physically separate storage; no transaction processing, recovery or concurrency control; only loading and read access.
OLTP (database)OLAP (warehouse)
OrientationCustomer, transactionMarket, analysis
DataCurrent, detailedHistorical, summarized, huge
DesignER model, application-orientedStar or snowflake, subject-oriented
ViewCurrent, localEvolutionary, integrated
AccessRead and write, short transactionsMostly read, complex queries

Why separate them? Running analysis on the operational database hurts its performance. OLTP needs concurrency control and recovery that slow analytical queries. Analysis needs consolidated, historical data from many sources.

Architecture, models, ETL

Three-tier architecture: (bottom) warehouse database server fed by external sources through extract, clean, transform, load and refresh; (middle) OLAP server (ROLAP or MOLAP); (top) front-end query, report and mining tools.

  • Enterprise warehouse: covers the whole organization, one admin view.
  • Data mart: a subset for a specific group or subject (independent or dependent).
  • Virtual warehouse: a set of views over operational databases; only some summaries are materialized.

Metadata repository stores the schema, source mappings, hierarchies and the operational history of the warehouse. The recommended approach is incremental: build data marts and integrate them into an enterprise view over time.

Data cube and the lattice of cuboids

A data cube models data along dimensions (time, item, location, supplier) and stores measures (dollars sold) in a fact table. Each combination of dimensions is a cuboid. The base cuboid has all n dimensions; the apex cuboid (0-D) is the grand total, “all”. Together the cuboids form a lattice.

Number of cuboids (no hierarchies) = 2ⁿ With hierarchies = Π (Lᵢ + 1), i = 1..n (Lᵢ = number of levels of dimension i, not counting “all”)

Book: §4.2.1 “Data Cube: A Multidimensional Data Model”. Notes: 03/09/26, 14/09/26.

Go deeper: §4.2.1 Cube and lattice →

Schemas: star, snowflake, fact constellation
  • Star: one central fact table (foreign keys plus measures) linked to one denormalized table per dimension. Simple and fast; the usual choice for warehouses.
  • Snowflake: a star where dimension tables are partially normalized into more tables. Saves space but needs more joins.
  • Fact constellation (galaxy): several fact tables share dimension tables; suits multiple subjects.

Book: §4.2.2 “Stars, Snowflakes, and Fact Constellations: Schemas for Multidimensional Data Models”. Notes: 10/09/26.

Measures and OLAP operations

Measure categories:

  • Distributive: computing on partitions then combining equals computing on all data (sum, count, min, max).
  • Algebraic: computed from a fixed number of distributive results (average = sum/count).
  • Holistic: no fixed-size summary suffices (median, mode, rank).

OLAP operations:

  • Roll-up: climb a hierarchy or drop a dimension (city → country).
  • Drill-down: the reverse, to more detail (country → city).
  • Slice: select on one dimension, giving a sub-cube.
  • Dice: select on two or more dimensions.
  • Pivot (rotate): swap axes to give a different view.

Server types: ROLAP (relational), MOLAP (array-based multidimensional), HOLAP (hybrid).

Book: §4.2.4 “Measures: Their Categorization and Computation”, §4.2.5 “Typical OLAP Operations”, §4.4.4 “OLAP Server Architectures: ROLAP versus MOLAP versus HOLAP”. Notes: 10/09/26, 14/09/26.

Design process, materialization and indexing

Design approaches: top-down (enterprise warehouse first, then marts), bottom-up (marts first, then integrate), or a combination. Steps: choose business process, grain, dimensions, measures.

Materialization (precompute cuboids): none (slow queries, no storage), full (fast, huge storage), partial (precompute the frequently used ones; the practical choice).

Indexing:

  • Bitmap index: one bit vector per attribute value, so selections use fast bit operations. Best for low-cardinality attributes.
  • Join index: precomputes joins between dimension values and fact table rows.

Book: §4.3.2 “Data Warehouse Design Process”, §4.4.1 “Efficient Data Cube Computation: An Overview”, §4.4.2 “Indexing OLAP Data: Bitmap Index and Join Index”. Notes: 14/09/26, 15/09/26.

Concept hierarchies and OLAP query processing
  • Concept hierarchy: maps low-level concepts to higher-level ones (street < city < state < country). It can be a total order, a partial order (day < month < quarter and day < week, both below year), or a set-grouping hierarchy (price ranges).
  • Choosing a cuboid: use the cheapest materialized cuboid that has the needed dimensions at the same or a finer level. A cuboid at country level cannot answer a state-level question, because finer data cannot be rebuilt from coarser data.
  • Server types: ROLAP (relational, most scalable), MOLAP (array-based, fast, wastes space on sparse data), HOLAP (hybrid).
  • Other cube terms: iceberg cube (keep cells above a threshold), shell cube (precompute only a few dimensions), drill-across and drill-through.

Book: §4.2.3 “Dimensions: The Role of Concept Hierarchies”, §4.4.3 “Efficient Processing of OLAP Queries”, §4.4.4 “OLAP Server Architectures: ROLAP versus MOLAP versus HOLAP”.

Other books: what they add
  • Kimball’s four-step design: choose the business process, declare the grain, identify the dimensions, identify the facts. This is Han’s §4.3.2 in other words.
  • Fact table types (Kimball): transaction, periodic snapshot, accumulating snapshot. Facts can be additive, semi-additive (a balance adds across accounts but not across time) or non-additive (ratios).   • Conformed dimensions and the bus architecture: data marts share common dimensions (date, product, customer) so they integrate. This is how Kimball achieves the “bottom-up with integration” idea in Han’s recommended approach.
  • Slowly changing dimensions: Type 1 overwrites the value; Type 2 adds a new row and keeps history; Type 3 adds a column. They show how a warehouse stays time-variant.
  • Inmon vs Kimball: Inmon builds a normalized enterprise warehouse first and derives dependent marts (top-down); Kimball builds dimensional marts joined by conformed dimensions (bottom-up). Han’s enterprise warehouse, data marts and recommended approach sit between the two.

Basics: support, confidence, closed and maximal
support(A ⇒ B) = P(A ∪ B) = count(A ∪ B) / total transactions confidence(A ⇒ B) = P(B | A) = count(A ∪ B) / count(A)

A rule is strong if it meets both min_sup and min_conf. A set is a frequent itemset if its support count ≥ the threshold.

Apriori property: every subset of a frequent itemset is frequent (equivalently, any superset of an infrequent set is infrequent). This is what allows pruning.

  • Closed frequent itemset: frequent, and no proper superset has the same support count.
  • Maximal frequent itemset: frequent, and no proper superset is frequent.
Notes’ example: {a₁…a₁₀₀}:1 and {a₁…a₅₀}:2 with threshold 1. Closed = both. Maximal = only the first.

Apriori algorithm and rule generation
  1. Scan the database to count each item (C₁). Keep those ≥ min_sup as L₁.
  2. Join Lₖ₋₁ with itself to form candidates Cₖ.
  3. Prune any candidate with an infrequent (k−1)-subset (Apriori property).
  4. Scan to count candidates; keep frequent ones as Lₖ.
  5. Repeat until no new frequent set appears.

Generating rules: for each frequent itemset l and each non-empty subset s, output s ⇒ (l − s) if count(l)/count(s) ≥ min_conf. All rules from one itemset share the same support but differ in confidence.

Improving efficiency: hash-based itemset counting, transaction reduction, partitioning, sampling, dynamic itemset counting. The drawbacks are many candidates and repeated database scans.

Notes check: confidence(A ⇒ B) = P(B | A) = count(A ∪ B)/count(A), so the count of the left side is the denominator. A k-itemset gives 2k − 2 candidate rules. If a rule s ⇒ (l − s) fails min_conf, every rule with a smaller left side from the same itemset fails too.

Book: §6.2.1 “Apriori Algorithm: Finding Frequent Itemsets by Confined Candidate Generation”, §6.2.2 “Generating Association Rules from Frequent Itemsets”, §6.2.3 “Improving the Efficiency of Apriori”. Notes: 23/09/26, 24/09/26.

FP-growth with the worked example

FP-growth avoids candidate generation: it compresses the database into an FP-tree and mines it by pattern growth.

T1 {E,K,M,N,O,Y} T2 {D,E,K,N,O,Y} T3 {A,E,K,M} T4 {C,K,M,U,Y} T5 {C,E,I,K,O,O} min_sup = 3
  1. Count items: K5, E4, M3, O3, Y3 are frequent; A, C, D, I, N, U are dropped.
  2. Order each transaction by descending frequency: T1 {K,E,M,O,Y}, T2 {K,E,O,Y}, T3 {K,E,M}, T4 {K,M,Y}, T5 {K,E,O}.
  3. Build the tree from a null root; shared prefixes increase node counts (K:5 at the top).
  4. Conditional pattern base for each item (prefix paths): Y {K,E,M,O:1}, {K,E,O:1}, {K,M:1}; O {K,E,M:1}, {K,E:2}; M {K,E:2}, {K:1}; E {K:4}.
  5. Conditional FP-tree keeps items whose summed count ≥ 3: Y gives {K:3}; O gives {K:3, E:3}; M gives {K:3}; E gives {K:4}.
  6. Frequent patterns: {K,Y:3}; {K,O:3}, {E,O:3}, {K,E,O:3}; {K,M:3}; {K,E:4}.
Check: O appears in T1, T2 and T5, so its count is 3. If you wrote 4 for the O patterns in your notes, correct it to 3.

Eclat is the vertical-format alternative: store each item with its transaction-ID set and intersect the sets to get support.

Which patterns are interesting? (lift and χ²)

High support and confidence do not guarantee an interesting rule: A ⇒ B can be misleading if B is already very common.

lift(A,B) = P(A ∪ B) / (P(A) P(B)) lift > 1 positive correlation, = 1 independent, < 1 negative

The rule becomes A ⇒ B [support, confidence, correlation]. χ² also tests correlation (same method as Chapter 3). For large datasets with many null transactions, prefer null-invariant measures: all_confidence, max_confidence, Kulczynski, cosine.

Book: §6.3 “Which Patterns Are Interesting?—Pattern Evaluation Methods”, §6.3.1 “Strong Rules Are Not Necessarily Interesting”, §6.3.2 “From Association Analysis to Correlation Analysis”, §6.3.3 “A Comparison of Pattern Evaluation Measures”.

More methods: efficiency, Eclat, and closed and maximal mining
  • Improving Apriori: hash-based counting (buckets below min_sup cannot hold frequent pairs), transaction reduction, partitioning (two scans: local frequent sets, then one global count), sampling, dynamic itemset counting.
  • Eclat (vertical format): keep {item : TID set}; the support of an itemset is the size of the intersection of TID sets. A diffset stores only the difference, so support = support(X) − |diffset|.
  • Mining closed and maximal itemsets directly: item merging, sub-itemset pruning, item skipping, with superset and subset checking.
  • Worked example: Table 6.1 (min_sup = 2) has 13 frequent itemsets, 9 closed and 3 maximal ({I2,I4}, {I1,I2,I3}, {I1,I2,I5}).
  • Comparison: Apriori generates and tests candidates with one scan per level; FP-growth uses two scans and no candidates; Eclat uses one scan to convert, then intersections.

Book: §6.2.3 “Improving the Efficiency of Apriori”, §6.2.5 “Mining Frequent Itemsets Using Vertical Data Format”, §6.2.6 “Mining Closed and Max Patterns”.

Other books: what they add
  • Tan et al. form candidates by Fk−1 × F1 or Fk−1 × Fk−1 merging (Han’s Apriori join is the second) and count support with a hash tree.
  • Interestingness measures (Tan, Zaki & Meira): lift (interest factor) = P(AB)/(P(A)P(B)); leverage = P(AB) − P(A)P(B); conviction = (1 − sup(B))/(1 − conf(A ⇒ B)); the φ-coefficient. Simpson’s paradox: a correlation can reverse when the data are split into subgroups.
  • Zaki & Meira cover Apriori, Eclat (tidset intersection and diffsets) and FPGrowth, then summarize itemsets with maximal (GenMax) and closed (Charm) sets.
  • In every book: maximal ⊆ closed ⊆ frequent, and support is antimonotone.

Tan et al., chapter “Association Analysis: Basic Concepts and Algorithms”; Zaki & Meira, Ch. 8 “Itemset Mining”, Ch. 9 “Summarizing Itemsets”, Ch. 12 “Pattern and Rule Assessment”.

Exam checklist: what you must be able to do
  • Write support = count(A ∪ B)/|D| and confidence = count(A ∪ B)/count(A).
  • Decide whether an itemset is closed and/or maximal by checking all proper supersets.
  • Run Apriori: Ck, counts, Lk, join then prune (state why each candidate is pruned), stop when empty.
  • List every rule from a frequent itemset (2k − 2) with its confidence and mark the strong ones.
  • Run FP-growth: item counts, descending order, build the tree, conditional pattern bases, conditional FP-trees, frequent patterns.
  • Explain Eclat with TID-set intersection; compute lift and χ²; name Kulczynski and the imbalance ratio as the recommended pair.
