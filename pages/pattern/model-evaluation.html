Evaluating learning methods: deep dive

How to measure what a model will really do on new data: test and validation sets, cross-validation, confusion matrices and all the metrics, ROC and precision-recall curves, confidence intervals, significance tests, and the pitfalls that fool even careful people.

Read: Mitchell, Machine Learning, Ch. 5 "Evaluating Hypotheses": §5.2 "Estimating Hypothesis Accuracy" (sample error vs true error, confidence intervals for discrete-valued hypotheses), §5.4 "A General Approach for Deriving Confidence Intervals", §5.5–5.6 "Difference in error of two hypotheses" and "Comparing learning algorithms" (paired t tests). Bishop, PRML, §1.3 "Model Selection" (cross-validation, leave-one-out). Duda, Hart & Stork, Ch. 9 "Algorithm-Independent Machine Learning": §9.6 "Resampling for Estimating Statistics" (jackknife, bootstrap) and §9.7 "Estimating and Comparing Classifiers". Hastie, Tibshirani & Friedman, Elements of Statistical Learning, §7.10 "Cross-Validation" (incl. §7.10.2 "The wrong and right way to do cross-validation"). Fawcett (2006), "An introduction to ROC analysis". Slide sources: D. Page (CS 760, Wisconsin) and the CS 40003 data-analytics notes. Section numbers follow the usual editions; check your copies.

1. The question

How well will this model work on data it has never seen? The error on the training data is useless for answering this: a model can memorise the training set (overfitting, chapter 1) and score 100%. Training error keeps falling as the model gets more complex, while test error is U-shaped. Evaluation is the discipline of getting an unbiased estimate of future performance, and then deciding whether a difference between two models is real or luck.

2. Test sets, validation sets, learning curves

Test set

Labelled data are split into a training set (to learn) and a test set (to estimate accuracy). The rule: pretend the test data are "in the mail". If the test labels influence the learned model in any way (choosing features, tuning parameters, picking the threshold), the accuracy estimate is biased upwards. (Exception: in some applications you may use the test feature vectors x, but never the labels.)

Validation (tuning) set

Often we need unbiased accuracy estimates during learning, for example to choose the pruning level of a decision tree, the k in k-NN, or C and γ for an SVM. Do not use the test set for this. Partition the training data again into a smaller training set and a validation set: learn candidate models on the former, pick the best by accuracy on the latter, then evaluate the chosen model once on the untouched test set. (Slide figure: "Choose the best model" in the diagram of data → training/test → models 1…n.)

Learning curves

How does accuracy change with the training-set size? Plot a learning curve: for each sample size s (optionally repeating n times), randomly select s training instances, learn, evaluate on the test set, and plot (s, accuracy) (with the average and error bars if repeated). A curve still rising at the largest s says "more data would help"; a flat curve says the model, not the data, is the limit.

Limitations of a single split

  • We may not have enough data to make both sets large.
  • A larger test set gives a more reliable (lower-variance) accuracy estimate; but a larger training set is more representative of the data we actually have. These pull in opposite directions (typical test share 20–50%, "Size of test set: 50~30%").
  • One split cannot show how sensitive accuracy is to the particular training sample: a lucky or unlucky split gives "bad performance" for one split and "good performance" for another, from the same data.

Random resampling and stratified sampling

Random resampling repeats the random train/test partition many times and averages. Stratified sampling keeps the class proportions in each selected set: first group the instances by class, then randomly pick from each group. Example: 12 positives and 8 negatives (3:2) split into train, validation and test should keep roughly 3:2 in each, which matters for small or imbalanced data.

3. Cross-validation

Partition the data into n subsamples (folds) s₁…sn. For each i in turn: train on all folds except si, test on si. Every instance is tested exactly once, and the n results are combined.

fold i: train on all folds except s_i | test on s_i | correct_i accuracy = (Σ correct_i) / (total instances)

Slide example: 100 instances, 5 folds of 20: correct 11/20, 17/20, 16/20, 13/20, 16/20, so accuracy = (11 + 17 + 16 + 13 + 16)/100 = 73/100 = 73%.

  • 10-fold is common; smaller n is used when training is slow.
  • Leave-one-out CV: n = number of instances (each test fold is one instance). Uses nearly all the data for training; most expensive.
  • Stratified CV: stratified sampling when forming folds.
  • CV makes efficient use of the data for testing (every instance is a test instance once).
  • With CV or random resampling we evaluate a learning method, not an individual learned model, because each fold trains a different model.

Internal (nested) cross-validation for model selection

Instead of one validation set, use CV inside the training set to choose the model, e.g. k in k-NN:

  1. Partition the training set into n folds s₁…sn.
  2. For each candidate k: for i = 1…n, learn a k-NN model on all folds but si and measure accuracy on si.
  3. Choose the k with the best average accuracy.
  4. Learn the final model on the entire training set with that k, and test it on the test set.

These steps are run independently inside each outer training set, so the test fold never influences the choice of k.

4. Confusion matrix and metrics

A single accuracy number hides what kind of mistakes the model makes. The confusion matrix tabulates predictions against truth (error matrix):

Actual positiveActual negative
Predicted positiveTP (true positive)FP (false positive)
Predicted negativeFN (false negative)TN (true negative)

Medical-test reading: TP = has the disease and the test says so; TN = does not and the test says so; FP = does not have it but the test says it does; FN = has it but the test misses it. Let P = TP + FN (actual positives) and N = FP + TN (actual negatives).

accuracy = (TP + TN) / (TP + FP + FN + TN) TPR = recall = sensitivity = hit rate = TP / P = TP / (TP + FN) FPR = FP / N = FP / (FP + TN) = 1 − specificity specificity (TNR) = TN / N = TN / (TN + FP) precision (PPV) = TP / (TP + FP) fraction of positive predictions that are correct F1 (F-measure) = 2·precision·recall / (precision + recall) = 2TP / (2TP + FP + FN) harmonic mean

Why accuracy alone is not enough

  • Class skew: is 98% accuracy good if 97% of instances are negative? A model that always says "negative" gets 97% and finds no positives at all.
  • Different costs: a false positive in medicine may cost an extra test; a false negative may mean an untreated disease.
  • Often we care only about the high-confidence predictions.

Example: 1 000 instances with 30 positives. TP = 20, FN = 10, FP = 40, TN = 930: accuracy = 950/1000 = 95% (below the 97% of "always negative"!), recall = 20/30 = 0.667, FPR = 40/970 = 0.041, precision = 20/60 = 0.333, F1 = 40/90 = 0.444. The always-negative model has higher accuracy but recall 0; accuracy ranks the models the wrong way round for this task.

"Accuracy" and "precision" in measurement are different words: the slides' target diagrams show accuracy (closeness of the average to the true value, i.e. low bias) and precision (spread of repeated measurements, i.e. low variance). In classification, "precision" means TP/(TP + FP). Do not mix the two meanings.

More than two classes: macro and micro averaging

Compute precision and recall per class (one-versus-rest, from the confusion-matrix column and row sums), then either macro-average (mean of the per-class values: every class counts equally) or micro-average (pool TP, FP, FN over all classes first: every instance counts equally, frequent classes dominate). In single-label problems micro-precision = micro-recall = accuracy. Example (past paper S25): rows (50,5,5), (10,30,10), (5,10,25): per-class precision 0.769, 0.667, 0.625; recall 0.833, 0.600, 0.625; macro precision 0.687, macro recall 0.686, macro F1 (mean of per-class F1) 0.686; micro P = R = F1 = 105/150 = 0.70.

5. ROC and precision-recall curves

Most classifiers output a score (confidence that an instance is positive) and a threshold turns it into a label. Moving the threshold trades one kind of error for the other. Slide intuition: with overlapping score distributions for diseased and healthy people, a cut-off of 50 gives some FN and FP; moving it down ("everyone is positive") gives sensitivity 100% but specificity 0; moving it up does the reverse. The ROC curve (receiver operating characteristic) plots TPR against FPR as the threshold varies. (Why 1 − specificity? FPR = FP/N = 1 − TN/N = 1 − specificity.) The name comes from WWII radar signal-detection theory (receiver operators distinguishing aircraft from noise).

Algorithm to build an ROC curve

  1. Sort the test predictions by confidence that the instance is positive, highest first.
  2. Step down the list; at each threshold between instances of opposite classes (keep tied scores on the same side), compute TPR and FPR for the instances above the threshold.
  3. Output the (FPR, TPR) point; join the points.

Thresholds placed after Ex7, Ex1, Ex6, Ex3, Ex5, Ex8 give (FPR, TPR) = (0, 2/5), (1/5, 2/5), (1/5, 4/5), (3/5, 4/5), (3/5, 1), (1, 1). The curve climbs when a positive is passed and moves right when a negative is passed. Area under this curve = 0.2·0.4 + 0.4·0.8 + 0.4·1.0 = 0.80.

Reading a ROC curve

  • (0,0): never predict positive. (1,1): always predict positive. (0,1): perfect (the "ideal point"). The diagonal is random guessing (expected curve for random guessing).
  • One point is better than another if it is to the north-west (higher TPR, lower FPR, or both). Points below the diagonal are worse than random (flip the predictions).
  • The left-hand side near the y-axis is "conservative" (positive only with strong evidence: few FP, but often low TPR); the upper right is "liberal" (nearly all positives found, but many FP).
  • A classifier giving only labels (e.g. a plain decision tree) is a single point; interpolating between points (convex hull) is achievable by randomly choosing between two classifiers.
  • AUC (area under the curve) summarises the curve: 0.9–1 excellent, 0.8–0.9 good, 0.7–0.8 fair, 0.6–0.7 poor, 0.5–0.6 fail. It equals the probability that a randomly chosen positive gets a higher score than a randomly chosen negative.
  • Different methods can win in different parts of ROC space, depending on the costs of false positives and false negatives. With costs known, the best operating point is where the curve touches a line of slope (N·costFP)/(P·costFN) (slides: the best point moves up-right if false negatives cost 10× more, down-left if false positives do). (Slope formula: standard result, Fawcett 2006.)

ROC vs precision-recall

ROC is insensitive to class distribution (the curve does not change if the proportion of positives in the test set changes) and can identify the best threshold for given costs. But a low FPR does not mean most positive predictions are right. With TPR = 0.9 and FPR = 0.01, precision = TPR·π / (TPR·π + FPR·(1 − π)), where π is the fraction of positives:

Fraction of instances that are positive (π)0.50.10.010.001
Fraction of positive predictions that are correct0.9890.9090.4760.083

(Verified by the formula.) So for rare positives (disease screening, fraud), a "great" ROC point can still mean most alarms are false. A precision-recall (PR) curve plots precision against recall (= TPR) as the threshold varies; the ideal point is (1,1), the baseline precision equals the fraction of positives, and PR curves suit tasks with many negative instances. Both curves assume binary tasks and are often summarised by the area under the curve.

With cross-validation, how do we get one curve? Approach 1: assume the confidence values are comparable across folds, pool all predictions, and plot one curve. Approach 2 (ROC): plot each fold's curve, view each as a function, and plot the average curve.

6. Confidence intervals on error

A test-set accuracy is itself a random quantity. Given a model h, a test set S of n instances drawn independently of one another and of h, with n ≥ 30, and r errors:

error_S(h) = r/n (best estimate of the true error) with approximately N% probability the true error lies in error_S(h) ± z_N · √( error_S(h)(1 − error_S(h)) / n )
Confidence N%50688090959899
zN0.671.001.281.641.962.332.58

Where it comes from: (1) the number of errors on n independent instances follows a binomial distribution with parameters n and the true error p; (2) for n ≥ 30 and p not extreme, the normal distribution approximates the binomial well; (3) the N% interval is the set of bounds containing N% of the probability mass of that normal.

Examples: n = 100, r = 20: error 0.20, 95% interval 0.20 ± 1.96·√(0.2·0.8/100) = 0.20 ± 0.078 = [0.122, 0.278]. n = 400, r = 80: same error but ±0.039. The width shrinks like 1/√n: quadrupling the test set halves the interval. n = 50, r = 10: ±0.11, a wide [0.09, 0.31].

Bootstrap confidence bounds (empirical)

Given n examples, draw n with replacement (a bootstrap sample); repeat the whole evaluation (e.g. the full cross-validation); do this 1 000 or 10 000 times; the lower (upper) bound is the value such that 2.5% of the runs fall below (above) it. It makes no normality assumption. For the 20-errors-in-100 example (resampling the 100 outcomes 10 000 times) the 95% interval is [0.13, 0.28], close to the formula's.

7. Comparing learning systems

Is system 1 really better than system 2, on one task or across tasks?

Motivating example (slide): accuracies on the test folds, system 1: 80, 50, 75, …, 99; system 2: 79, 49, 74, …, 98. The means are close and the standard deviations overlap heavily, but system 1 is better in every fold (δ = +1 each time). Ignoring the pairing would hide that.

Paired t-test

  1. Treat the per-fold differences δi (system 1 − system 2 on the same fold) as i.i.d. observations. Null hypothesis: the two systems have the same accuracy (mean δ = 0). Alternative: one is more accurate.
  2. Sample mean δ̄ = (1/n)Σδi.
  3. Statistic: t = δ̄ / √[ (1/(n(n − 1))) Σ(δi − δ̄)² ] (mean divided by its standard error).
  4. Look up t in Student's t distribution with n − 1 degrees of freedom to get the p-value.
  5. If p is sufficiently small (typically < 0.05), reject the null hypothesis.

Two-tailed: we ask "is the accuracy of the two systems different?", because a priori we do not know which will be better; a one-tailed test asks "is A better than B?" and is only justified when only that direction matters.

Worked example (verified in code): 10 folds, system 1 accuracies 80, 50, 75, 90, 85, 60, 70, 95, 65, 99; per-fold differences δ = +1, +2, +1, +3, 0, +2, +1, +2, +1, +2. Then δ̄ = 1.5, standard deviation of δ = 0.85, standard error = 0.85/√10 = 0.269, so t = 5.58 with 9 degrees of freedom. The critical value for two-tailed 5% is 2.26, so p = 0.0003: a significant difference. The same data in an unpaired test (means 76.9 vs 75.4, standard deviations ≈ 15.8 for both) give t = 0.21, p = 0.83: no evidence at all. Pairing removes the fold-to-fold variation that both systems share.

Sign test (small data)

With fewer than about 300 examples there are not 30 test instances per fold, so prefer leave-one-out CV. Count the "wins" for A and for B over the N test examples on which they disagree; let M be the larger count. The p-value is the probability, under a binomial b(N, 0.5), that either A or B wins at least M times. Example: 10 disagreements, A wins 9: p = 2·(10 + 1)/1024 = 0.021 (significant); A wins 8: p = 0.109 (not significant).

Scatter plots and lesion studies

  • Scatter plot: plot (performance of A, performance of B) across many data sets; points above the diagonal mean B wins there. It shows how often and by how much, not just the average.
  • Lesion study: remove (lesion) a component (e.g. a feature type) of the system and see how performance changes (the slides show ROC curves after removing each feature type). This tells you what contributes to performance.

8. Pitfalls: how people fool themselves

The slides ask three questions before trusting a cross-validated number:

  1. Is the held-aside test data really representative of data you would collect in the future? Example: cancer samples processed by different people or on different days than the controls. A classifier can learn the batch instead of the disease. Randomise.
  2. Did I repeat my entire data-processing procedure on every fold, using only that fold's training data? Never access a test label. Any preprocessing over the whole data set that uses labels (feature selection, parameter tuning, threshold selection) leaks information.
  3. Have I modified my algorithm so many times on this same data set that I (the human) am overfitting it? If so, collect fresh data to test on.
Pitfall 2 in numbers (simulation): 50 samples, 5 000 random features, random labels (nothing to learn, true accuracy 50%). Choosing the 20 "best" features using all the data and then running 5-fold CV with 3-NN reports about 95% accuracy (average of 20 repeats). Putting the feature selection inside each fold's training step reports 54%, the honest answer. The labels leaked into the features through the early selection. (Hastie et al., §7.10.2.)

Template: ROC from scores

  1. Count P and N. For each given threshold t, predict positive if score ≥ t.
  2. Count TP and FP at each t; compute TPR = TP/P and FPR = FP/N.
  3. Add (0,0) and (1,1), plot FPR on x, TPR on y, join the points, add the diagonal.

Common mistakes

  • Reporting training accuracy as if it predicted test accuracy.
  • Tuning hyperparameters on the test set (or reusing the test set many times).
  • Choosing features or the threshold on all the data before cross-validation.
  • Using accuracy on imbalanced data; mixing up precision (over predicted positives) and recall (over actual positives); computing FPR as FP/(FP + TP) instead of FP/N.
  • Using an unpaired test when the same folds were used for both systems; forgetting that the paired t-test has n − 1 degrees of freedom and is two-tailed.
  • Believing a high AUC means precision is high when positives are rare.

Self-test

1. Fold results 8/10, 9/10, 7/10, 9/10, 7/10 (10 instances per fold). CV accuracy?
(8 + 9 + 7 + 9 + 7)/50 = 40/50 = 80%.
2. TP = 40, FP = 10, FN = 20, TN = 130. Accuracy, recall, precision, FPR, F1?
Accuracy = 170/200 = 0.85; recall = 40/60 = 0.667; precision = 40/50 = 0.80; FPR = 10/140 = 0.071; F1 = 80/(80 + 10 + 20) = 0.727.
3. A model has 5% error on 200 test instances. 95% confidence interval?
0.05 ± 1.96·√(0.05·0.95/200) = 0.05 ± 0.030, so [0.020, 0.080].
4. TPR = 0.8, FPR = 0.05, π = 0.02. Precision?
0.8·0.02 / (0.8·0.02 + 0.05·0.98) = 0.016/(0.016 + 0.049) = 0.246: three out of four alarms are false.
5. Why must feature selection be repeated inside each cross-validation fold?
Otherwise the selection has seen the test fold's labels, so the chosen features are tuned to the test data and the CV accuracy is optimistically biased (up to 95% on pure noise in the simulation above).
6. Two systems differ by about +1 point on every fold. Which test, and why?
The paired t-test (n − 1 degrees of freedom, two-tailed) on the per-fold differences: it exploits the consistent sign, while an unpaired test would be swamped by the large fold-to-fold variation shared by both systems.
