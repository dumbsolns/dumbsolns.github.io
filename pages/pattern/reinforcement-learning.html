Reinforcement learning: deep dive

From the agent–environment loop to Q-learning and DQN, with every formula built step by step and one example (the car MDP) carried through the whole page.

Read: Sutton & Barto, Reinforcement Learning: An Introduction (2nd ed.): Ch. 1 "Introduction", Ch. 3 "Finite Markov Decision Processes" (§3.1 The Agent–Environment Interface, §3.3 Returns and Episodes, §3.5 Policies and Value Functions, §3.6 Optimal Policies and Optimal Value Functions), Ch. 4 §4.4 "Value Iteration", Ch. 2 §2.2 "Action-value Methods" (ε-greedy), Ch. 6 §6.1 "TD Prediction" and §6.5 "Q-learning: Off-policy TD Control". Deep RL: Mnih et al. (2015), "Human-level control through deep reinforcement learning", Nature; S&B Ch. 16 §16.5. Bishop's PRML does not cover RL.

1. Why reinforcement learning?

Supervised learning (regression, classification, SVM, Naive Bayes) needs a labelled answer for every input. Often nobody can supply it: what is the "correct" move in chess, or the correct torque for a robot joint? Instead we can tell the learner how well it did afterwards. That is RL: sequential decision making with evaluative feedback.

Examples from the slides: cart-pole (state: angle, angular speed, position, velocity; action: horizontal force; reward 1 per step the pole stays up), robot locomotion (state: joint angles/velocities; action: torques; reward: stay upright and move forward), Atari (state: raw pixels; action: joystick; reward: score change), Go (state: board; action: where to place; reward 1 for a win at the end, else 0).

What makes RL harder than supervised learning

  • Evaluative feedback: you are told how good your action was, not which action was best, so you must try things.
  • Delayed feedback: the move that loses a chess game may have been made 40 moves earlier (the credit assignment problem).
  • Non-stationary data: the states you see depend on your current policy, so the data distribution changes as you learn.
  • Exploration vs exploitation: repeat the best-known action, or try another that could be better?

2. The Markov decision process (MDP)

The mathematical model of the loop is a tuple (S, A, T, R, γ):

  • S: set of states. A: set of actions.
  • T(s,a,s′) = P(s′ | s, a): the probability of reaching s′ from s by doing a. For fixed (s,a), it is a distribution over s′, so Σs′ T(s,a,s′) = 1.
  • R(s,a,s′): the reward received when doing a in s and landing in s′.
  • γ ∈ [0,1]: the discount factor.

Markov property: the current state summarises everything relevant from the past: P(st+1 | st, at, st−1, …, s0) = P(st+1 | st, at). The interaction produces a trajectory s0, a0, r1, s1, a1, r2, … until a terminal state or a fixed horizon.

Fully vs partially observed: chess and Go are fully observed (the agent sees the true state). Poker or a first-person game gives only partial observations; then the agent must remember past observations (e.g. with a recurrent network).

Running example: the car

A robot car wants to travel far, quickly. States: Cool, Warm, Overheated (terminal). Actions: Slow, Fast. Going fast earns double reward but heats the car.

The slide notes E[R(Cool, Fast, ·)] = 0.5·2 + 0.5·2 = 2. The goal: choose actions so that the total reward is large.

3. Policy, return and discounting

A policy is the agent's strategy: deterministic π(s) = a or stochastic π(a|s) = P(At = a | St = s). Goal: find the optimal policy, the one with maximal value at every state.

What should "value" mean? Maximising only the next reward is short-sighted (a big reward now may lead into a trap, like Fast in Warm). Summing all future rewards can diverge for never-ending tasks. The fix is the discounted return:

G_t = R_{t+1} + γR_{t+2} + γ²R_{t+3} + … = Σ_{k=0}^{∞} γ^k R_{t+k+1}
  • A reward k steps away is worth γk of the same reward now (the slide's gems: worth 1, γ, γ², …).
  • Justification: (1) if rewards are bounded by Rmax the sum is at most Rmax/(1−γ), always finite; (2) the future is uncertain, so distant rewards count less; (3) immediate rewards are preferred over delayed ones; (4) it gives the recursion Gt = Rt+1 + γGt+1 that everything below relies on.
  • γ = 0: purely greedy. γ → 1: far-sighted. Typical values 0.9–0.99.
Problem with raw return: the future is stochastic (random transitions and, if π is stochastic, random actions). The agent cannot compute Gt before acting because it does not know which trajectory will happen. So we use the expected return, the value function.

4. Value functions and the Bellman equations

State value and action value

V_π(s) = E_π[ G_t | S_t = s ] how good is it to BE in s, following π Q_π(s,a) = E_π[ G_t | S_t = s, A_t = a ] how good is it to take a in s, THEN follow π

V converts an uncertain infinite future into one number per state. Q is "quality". They are linked: Vπ(s) = Σa π(a|s) Qπ(s,a).

Bellman expectation equation (recursive structure)

Substitute Gt = Rt+1 + γGt+1 into Vπ(s) = E[Gt|s]:

V_π(s) = E_π[ R_{t+1} + γ V_π(S_{t+1}) | S_t = s ] = Σ_a π(a|s) Σ_{s′} T(s,a,s′) [ R(s,a,s′) + γ V_π(s′) ] Q_π(s,a) = E[ R_{t+1} + γ Q_π(S_{t+1}, A_{t+1}) | S_t=s, A_t=a ]

Reading the double sum: average over what you might do (π), then over where you might land (T), of "reward now plus discounted value of where you land".

Optimality

A policy π* is optimal if Vπ*(s) = maxπ Vπ(s) for all s. All optimal policies share the same Q*. Replacing the average over actions by a max gives the Bellman optimality equation:

Q*(s,a) = E[ R_{t+1} + γ max_{a′} Q*(S_{t+1}, a′) | S_t=s, A_t=a ] V*(s) = max_a Q*(s,a) π*(s) = argmax_a Q*(s,a)
Key idea: once you know Q*, the optimal policy is free: in every state pick the action with the highest Q value. So the whole problem becomes "learn Q*".

5. When the model is known: value iteration

If T and R are known we can solve the Bellman optimality equation by repeatedly applying it (S&B §4.4): start with V = 0 and iterate V(s) ← maxa Σs′ T(s,a,s′)[R + γV(s′)]. Car MDP with γ = 0.9 (Overheated has V = 0):

Problem: real problems rarely come with T and R, and the state space can be huge. Hence model-free methods.

6. Model-free learning: TD and Q-learning

From expectation to samples

Without T the expectation in Bellman's equation cannot be computed. But the agent can take a step and observe one actual outcome (s, a, r, s′). Bootstrapping from the current estimate gives a sample target r + γV(s′). It is noisy (one sample, not the average), so don't overwrite; nudge the old estimate towards it:

V(s) ← V(s) + α [ (r + γV(s′)) − V(s) ] old rate sample target old estimate └──── TD error ───────────────┘

Done thousands of times, the averaging effect of α makes V converge to the true expected value. This is temporal-difference (TD) learning.

Q-learning update

Do the same for Q, using the optimality equation (max over next actions) in the target:

TD-error form: Q(s,a) ← Q(s,a) + α [ r + γ max_{a′} Q(s′,a′) − Q(s,a) ] weighted-average form: Q(s,a) ← (1−α) Q(s,a) + α [ r + γ max_{a′} Q(s′,a′) ]

The two forms are algebraically identical (expand the bracket). Roles: α ∈ [0,1] learning rate (α = 1 forgets the old value, α = 0 never learns); r + γ max Q(s′,a′) TD target ("label"); Q(s,a) prediction; the difference is the TD error.

The algorithm (with ε-greedy)

1. initialise Q(s,a) (e.g. all zeros) 2. for each episode: choose a starting state s 3. repeat until s is terminal: with probability ε → pick a random action a (explore) otherwise → a = argmax_a Q(s,a) (exploit) take a; observe r and s′ Q(s,a) ← Q(s,a) + α [ r + γ max_a′ Q(s′,a′) − Q(s,a) ] s ← s′
  • Why ε-greedy: a purely greedy agent can lock onto the first action that looked good and never discover better ones. A small ε keeps trying others. Common practice: start with large ε and decay it.
  • Off-policy: the target uses maxa′ (the greedy action) even though the behaviour was ε-greedy, so Q-learning learns Q* regardless of exploration (S&B §6.5). It converges to Q* if every (s,a) is visited infinitely often and α decays suitably.

Worked example on the car MDP (α = 0.5, γ = 0.9, all Q start at 0)

StepExperience (s, a, r, s′)UpdateNew Q
1(Cool, Fast, +2, Warm)0 + 0.5[2 + 0.9·0 − 0]Q(Cool,Fast) = 1.0
2(Warm, Slow, +1, Warm)0 + 0.5[1 + 0.9·0 − 0]Q(Warm,Slow) = 0.5
3(Cool, Fast, +2, Cool)1 + 0.5[2 + 0.9·1.0 − 1]Q(Cool,Fast) = 1.95
4(Warm, Fast, −10, Overheated)0 + 0.5[−10 + 0 − 0] (terminal: no future)Q(Warm,Fast) = −5

In step 3, maxa′Q(Cool,a′) = 1.0 (from step 1) enters the target: the good value of the next state has "flowed back" to Q(Cool,Fast). After many episodes Q → Q* = {14.95, 15.5, 14.5, −10}. Information about rewards propagates backwards one step per update, which is how delayed rewards are credited.

7. Deep RL: from a table to a neural network

Why tabular Q-learning fails: chess or driving has an astronomical number of states (Atari: raw pixels). You cannot store a table, and you will never visit most states. Even the slide's small grid has 8×7×4 = 224 entries; the table size is |S|·|A|. Solution: function approximation. A network Q(s,a;θ) learns patterns and generalises from visited to similar unvisited states.

Turning the TD error into a loss

In the TD update the target r + γ max Q(s′,a′) plays the role of a label y and Q(s,a) is the prediction. Supervised regression on that pair gives the MSE loss:

y = r + γ max_{a′} Q(s′, a′; θ⁻) (target; θ⁻ = frozen copy) L(θ) = E[ ( y − Q(s,a;θ) )² ] minimise by gradient descent on θ

Numerical feel: r = 1, γ = 0.9, max target-network Q(s′,·) = 5 → y = 1 + 4.5 = 5.5. If the network predicts Q(s,a) = 4, the loss is (5.5 − 4)² = 2.25 and the gradient pushes the prediction up.

DQN: the three ingredients

  • Main (online) network Qθ: updated at every step by gradient descent.
  • Target network Qθ⁻: a delayed, frozen copy of the main network, copied every C steps (e.g. 1000). Without it the target moves every time θ changes (chasing its own tail), which is unstable.
  • Replay buffer D: stores transitions (s,a,r,s′). Training on random mini-batches breaks the correlation between consecutive frames (the data would otherwise be highly correlated and non-stationary) and reuses experience.
for each step: 1. act: ε-greedy w.r.t. Q(s,·;θ); observe r, s′ 2. store (s,a,r,s′) in D 3. sample a random mini-batch from D y = r + γ max_a′ Q(s′,a′;θ⁻) (y = r if s′ is terminal) L(θ) = (y − Q(s,a;θ))²; update θ by gradient descent 4. every C steps: θ⁻ ← θ

Categories of modern RL (slides)

  • Value-based: approximate Q(s,a;θ), e.g. DQN.
  • Policy-based / actor-critic: directly parameterise the policy π(a|s;θ), output action probabilities or continuous motor values; e.g. PPO, SAC. Suited to continuous actions.
  • RLHF: a policy-gradient method (like PPO) guided by a reward model trained on human preference comparisons instead of a hard-coded game score. Used to fine-tune large language models.

Class example: combini and lecture hall

A 7×8 grid (56 positions). Goal: reach the nearest combini (+1, terminal) while avoiding the lecture hall (−1, terminal); every step to an empty cell costs −0.1. The step penalty makes shorter paths better, so the optimal policy gives the direction to the nearest combini from each cell while steering around the lecture hall. With 4 actions (N, E, S, W) the Q-table has 56×4 entries.

8. Exam kit

Likely questions (past papers: S23, S23i, F22, S25): Q-learning pseudo-code with the role of each term; MDP vs RL and additive discounted reward; deep RL vs Q-learning; model a robot task as an MDP.

Template answer: recycling-robot MDP (S23)

  • States: (battery: high / low) × (can in front: yes / no) × (holding can: yes / no), optionally plus location (near charger, near trash).
  • Actions: search/navigate, pick up can, throw into trash, go to charger, charge, wait.
  • Rewards: +1 per can thrown into the trash; a large negative reward (e.g. −10) if the battery dies; small step cost (e.g. −0.1) to encourage efficiency; 0 otherwise. With γ < 1 the robot collects many cans but recharges before the battery is empty, because dying loses all future rewards.

Common mistakes

  • Writing max over a instead of over the next action a′, or using Q(s′,a′) for the action actually taken (that is SARSA, not Q-learning).
  • Forgetting that a terminal next state has no future value (target = r).
  • Mixing up V (value of a state) and Q (value of a state-action pair).
  • Calling γ the learning rate. γ discounts the future; α is the learning rate.

Self-test

1. Why is the discount factor needed?
Keeps the infinite sum finite (≤ Rmax/(1−γ)), values sooner rewards over uncertain distant ones, and enables the Bellman recursion.
2. Why is the optimal policy easy once Q* is known?
π*(s) = argmaxa Q*(s,a): pick the best action in each state, no model needed.
3. In the car MDP, why is Slow optimal in Warm even though Fast pays double?
Fast in Warm overheats the car: reward −10 and the episode ends. Q*(Warm,Slow) = 14.5 ≫ Q*(Warm,Fast) = −10.
4. What does the TD error measure?
The gap between the sample target r + γ max Q(s′,a′) and the current estimate Q(s,a). Zero means the estimate is consistent with what was just observed.
5. Why do DQN's two networks and replay buffer exist?
The target network keeps the label y fixed for C steps (stable regression). The replay buffer decorrelates samples and reuses experience.
6. Compute: Q(s,a)=2, r=1, γ=0.9, α=0.1, max Q(s′,·)=4. New Q?
Target = 1 + 0.9·4 = 4.6; TD error = 4.6 − 2 = 2.6; Q = 2 + 0.1·2.6 = 2.26.
