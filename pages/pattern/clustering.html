Clustering: k-means and hierarchical, deep dive

How to find groups without labels: proximity measures, the SSE criterion, k-means (with proof that it converges and why it can get stuck), hierarchical linkage methods, and all the worked examples from the lectures and past papers.

1. What clustering is

Clustering is the process of grouping a set of objects into classes of similar objects, so that objects in a group are similar to one another and different from objects in other groups. It is unsupervised: there are no labels, and the aim is to discover new categories ("seek natural clusters in the data"). Compare classification, where the categories are known in advance.

Good clusteringMeaning
Intra-cluster distances smallsamples inside a cluster are close together
Inter-cluster distances largedifferent clusters are far apart

Applications (slides): gene-expression data (cluster genes and samples), face clustering (group photos of the same person), search-result clustering (group pages by topic), biology (taxonomy: kingdom, phylum, class, order, family, genus, species), information retrieval (document clustering), land use (areas of similar land use in earth-observation data), marketing (discover customer groups), city planning, earthquake studies, climate.

Three things you need

  1. A proximity measure: a similarity s(x, x′) (large if similar) or a dissimilarity/distance d(x, x′) (small if similar).
  2. A criterion function to evaluate a clustering (to tell a good clustering from a bad one).
  3. An algorithm to compute the clustering, e.g. by optimising the criterion.

How many clusters?

The same points can look like 2 clusters or 3 (slide "How many clusters?"). Two approaches: (1) fix the number k in advance; (2) find the best clustering according to the criterion function, letting the number of clusters vary. Extra (beyond the slides): the elbow method plots the criterion against k and looks for the bend. For the 7-point example in §5 the SSE is 37.07 (k = 1), 8.53 (k = 2), 2.50 (k = 3), 1.29 (k = 4), 0.67 (k = 5): it falls sharply up to k = 2 and then slowly, so k = 2 is the natural choice there. SSE always decreases as k grows (it reaches 0 when k = n), so you cannot just pick the minimum.

2. Proximity measures

A good proximity measure is very application dependent: clusters should be invariant under the transformations "natural" to the problem. For object recognition we want a rotated object to be at distance 0 (rotation invariance); for character recognition we do not want it (a rotated "6" must stay far from "9").

Distances (dissimilarity)

A (metric) distance d satisfies: non-negativity d(i,j) ≥ 0; identity d(i,i) = 0; symmetry d(i,j) = d(j,i); triangle inequality d(i,j) ≤ d(i,k) + d(k,j) (a detour is never shorter).

Euclidean (L2): d(x,y) = √( Σ_k (x_k − y_k)² ) straight line, translation invariant Manhattan / city block (L1): d(x,y) = Σ_k |x_k − y_k| cheaper to compute Chebyshev / supremum (L∞): d(x,y) = max_k |x_k − y_k| cheapest Minkowski (Lh norm): d(x,y) = ( Σ_k |x_k − y_k|^h )^(1/h), h ≥ 1 h=1: Manhattan, h=2: Euclidean, h→∞: supremum

Example (slide): x₁ = (1,2), x₂ = (3,5): Euclidean = √(2² + 3²) = 3.61; Manhattan = 2 + 3 = 5; supremum = max(2,3) = 3. Always sup ≤ Euclidean ≤ Manhattan. For binary vectors, Manhattan counts the number of positions that differ (Hamming distance), used in the hierarchical exercise below.

Similarity measures

  • Cosine similarity: s(x,y) = xᵀy / (‖x‖‖y‖): the cosine of the angle between the vectors; the smaller the angle, the larger the similarity. It is scale invariant (document length does not matter) and popular in text retrieval, where vectors are term frequencies with many zeros. Slide example: x = (5,0,3,0,2,0,0,2,0,0), y = (3,0,2,0,1,1,0,1,0,1): xᵀy = 25, ‖x‖ = 6.48, ‖y‖ = 4.12, so s = 25/(6.48·4.12) = 0.94, so the documents are very similar. It does not obey the metric axioms, so it is a nonmetric measure.
  • Correlation coefficient: popular in image processing; s = Σ(x_k − x̄)(y_k − ȳ) / √(Σ(x_k − x̄)² Σ(y_k − ȳ)²), invariant to shifting and scaling of intensities.

Feature scaling

Should length be measured in metres or centimetres, weight in grams or kilograms? In supervised learning we can normalise each feature to zero mean and unit variance. In clustering this is more problematic: if the variance in the data is due to the presence of clusters, normalising removes the very structure we want to find. Use judgement; do not normalise blindly.

The simplest clustering algorithm (threshold)

Go over all sample pairs and put them in the same cluster if the distance is below a threshold d₀ (or the similarity above s₀). Simple, but the result depends on d₀: too small gives too many tiny clusters, too large gives too few (everything merges), and a good d₀ is hard to choose automatically.

3. The criterion function: sum of squared errors

Partition n samples x₁…xn into c subsets D₁…Dc, with ni samples in Di and mean (centroid) μi = (1/ni) Σx∈Di x:

J_SSE = Σ_{i=1..c} Σ_{x ∈ D_i} ‖x − μ_i‖² minimise; c is fixed

It measures how well the c centroids represent the samples (total within-cluster squared distance). There are about cn/c! distinct partitions, so trying them all is impossible: finding the optimum of JSSE is NP-hard. In practice a greedy, iterative method works well: k-means.

4. k-means

MacQueen (1967); a partitional algorithm. Given the data set D = {x₁…xn}, xi ∈ Rr, and a user-specified k, it partitions D into k clusters, each with a centre called its centroid.

  1. Initialise: choose k (random) data points (seeds) as the initial centroids.
  2. Assign: assign each data point to the closest centroid (Euclidean).
  3. Update: recompute each centroid as the mean of its current members.
  4. Repeat steps 2–3 until convergence.

Stopping criteria: no (or minimal) re-assignment of points to different clusters; or no (or minimal) change of centroids; or a minimal decrease in SSE = Σj Σx∈Cj d(x, mj)².

Why it converges: each step decreases J

  • Assignment step (centroids fixed): moving a point to its nearest centroid can only reduce (or keep) its squared distance, so J cannot increase.
  • Update step (assignments fixed): for a cluster, d/dm Σ‖x − m‖² = −2Σ(x − m) = 0 gives m = mean of the members. The mean is the point that minimises the sum of squared distances, so J cannot increase.

J never increases, and there are only finitely many partitions, so the algorithm terminates after a finite number of iterations. But it only reaches a local optimum, not necessarily the global minimum.

Local optimum: a four-point example

Points (−3,1), (−3,−1), (3,1), (3,−1) and k = 2. Seeds (−3,0), (3,0) give left/right clusters with centroids (−3,0), (3,0) and J = 4 (the optimum). Seeds (0,1), (0,−1) give top/bottom clusters with centroids (0,1), (0,−1) that do not move: the algorithm halts at J = 36, nine times worse (slide "2-means gets stuck here"). Try both in the stepper below.

Seed choice and heuristics (slides)

Results can vary drastically with the seeds; some seeds converge slowly or to sub-optimal clusterings. Common heuristics: random centres in the space; randomly pick data points; pick points least similar to any existing centre (furthest-centres heuristic); try multiple starting points (keep the run with the lowest SSE); initialise with the result of another clustering method.

Strengths and weaknesses

StrengthsWeaknesses
Simple, easy to implement; most popular clustering algorithm.Needs the mean to be defined (for categorical data use k-modes: the most frequent value).

6. Hierarchical clustering

Instead of one flat partition, build a tree of nested clusters.

  • Agglomerative (bottom-up): start with each object as its own cluster; repeatedly merge the two most similar clusters until all objects are in one cluster. The more popular technique.
  • Divisive (top-down): start with all objects in one cluster; repeatedly select a cluster and split it into two until every leaf holds one object.

A dendrogram is the tree: each node is a cluster, each leaf a single object, and the height of a merge is the distance at which it happened. Cutting the dendrogram at a chosen height gives a clustering: each connected component below the cut is a cluster.

Agglomerative algorithm

  1. Compute the distance matrix.
  2. Let each data point be a cluster.
  3. Repeat: merge the two closest clusters; update the distance matrix.
  4. Until only a single cluster remains.

The key question is "how do we update the distance matrix?", that is, how to define the distance between two clusters.

Inter-cluster distances

MethodDefinitionStrengthsLimitations
MIN (single link)d(Ci,Cj) = min d(p,q), p∈Ci, q∈Cj: the closest pair; determined by one linkhandles non-elliptical shapessensitive to noise and outliers (chaining)
MAX (complete link)max d(p,q): the farthest pairless susceptible to noise and outlierstends to break large clusters; biased towards globular clusters
Group averageaverage of all pairwise distances between the clusterscompromise between single and complete; less susceptible to noisebiased towards globular clusters
Centroiddistance between cluster centroids d(mi, mj)cheap, intuitiveuses only the centres
Ward'sincrease in squared error (SSE) when the two clusters are merged; similar to group average with squared distancesless susceptible to noise and outliers; hierarchical analogue of k-means (can initialise k-means)biased towards globular clusters

Ward's merge cost for clusters A and B: ΔSSE = [nAnB/(nA + nB)]·‖mA − mB‖².

Cost, strengths, limitations

  • Space O(N²) (the distance matrix). Time O(N³) in many cases (N steps, each updating and searching an N² matrix); reducible to O(N² log N) for some approaches.
  • Strengths: no need to fix the number of clusters in advance (cut at any level); can match meaningful taxonomies (e.g. shopping sites: electronics → computers, cameras; furniture; groceries).
  • Limitations: once two clusters are merged the decision cannot be undone; no objective function is directly minimised; different schemes struggle with noise/outliers, clusters of different sizes, and irregular shapes.

  1. Smallest distance 0 (points 2 and 4 are identical): merge {2,4} at height 0.
  2. Single link: d({2,4},1) = min(2,2) = 2; d({2,4},3) = min(1,1) = 1; d(1,3) = 3. The smallest is 1: merge {2,4,3} at height 1.
  3. d({2,3,4},1) = min(2,3,2) = 2: merge everything at height 2.

With complete link the last merge is at height 3 (d(1,3) = 3); with group average it is at (2 + 3 + 2)/3 = 2.33. The shape of the tree is the same; the heights differ. Cutting between 1 and 2 gives two clusters {1} and {2,3,4}.

(b) Five points on a line: all linkages

Points A = 1, B = 2, C = 4, D = 7, E = 8. Distances: AB = 1, DE = 1, BC = 2, AC = 3, CD = 3, BD = 5, … Merge order is the same for every linkage here (AB, DE, then C joins {A,B}, then everything), but the heights differ:

Ward check: merging {A,B} (mean 1.5) with C: (2·1/3)·(4 − 1.5)² = 4.17; final merge of {A,B,C} (mean 2.33) with {D,E} (mean 7.5): (3·2/5)·(7.5 − 2.33)² = 32.03. The ΔSSE values add up to 37.2, the total SSE of all five points about their mean.

(c) Why MIN is "sensitive to noise" (chaining)

Two clear groups A = {0, 1, 2} and B = {8, 9, 10}. Single link joins them at height 6 (the gap 2 → 8). Add one stray point at 5 between them: now single link joins {A, 5} at 3 and then B at 3, so the two groups are fused at height 3 by a single noisy bridge point. Complete link is unaffected (it still joins at 10). This is why MIN handles odd shapes well but chains through noise, and MAX is more robust but may split large clusters.

Template: k-means by hand

  1. Write the initial centroids. For each point compute the distance to every centroid (a table) and mark the nearest; state the tie rule.
  2. List the clusters; compute the new centroids as the mean of x and y separately.
  3. Repeat. Stop when the assignment no longer changes; say so explicitly ("no change, converged").
  4. Give the final clusters and centroids (optionally the SSE).

Template: agglomerative by hand

  1. Distance matrix (lower triangle). 2. Merge the minimum entry; record the height.
  2. Update the matrix with the linkage rule (MIN: take the smaller of the two entries for each other cluster).
  3. Repeat until one cluster; draw the dendrogram with the heights on the axis.

Common mistakes

  • Updating centroids after each point instead of after assigning all points (that is online k-means, a different algorithm).
  • Stopping after one iteration without checking whether any point moved.
  • Using the maximum instead of the minimum for single link (or the reverse).
  • Drawing the dendrogram with merge heights that are not the cluster distances, or merging in the wrong order.
  • Normalising features automatically before clustering.
  • Claiming k-means always finds the global optimum.

Self-test

1. Distances between x = (2,7) and y = (5,3): Euclidean, Manhattan, Chebyshev?
Differences (3, 4): Euclidean 5, Manhattan 7, Chebyshev 4.
2. 1-D data {1, 2, 9, 10}, k = 2, initial centroids 1 and 2. Run k-means.
Iteration 1: 1 → C₁; 2 → C₂ (d = 0); 9, 10 → C₂. Centroids 1 and (2+9+10)/3 = 7. Iteration 2: 2 is now closer to 1 (1 vs 5): {1,2} and {9,10}; centroids 1.5 and 9.5. Iteration 3: no change. SSE = 0.25·4 = 1.0.
3. Distances d(a,b) = 1, d(b,c) = 2, d(a,c) = 4. After merging a and b, what is the distance to c for single, complete and average link?
Single: min(2,4) = 2. Complete: max(2,4) = 4. Average: (2 + 4)/2 = 3.
4. Why does k-means never increase J, yet may not find the best clustering?
Both the assignment step and the update step lower or keep J, so it converges; but it is a greedy local search, so different seeds can end in different local optima (e.g. J = 36 versus 4 on the rectangle).
5. Name two ways to choose or avoid choosing the number of clusters.
Fix k and compare SSE for several k (elbow); or use hierarchical clustering and cut the dendrogram at a chosen height.
6. Which linkage can chain two groups together through one noise point, and which resists it?
Single link (MIN) chains; complete link (MAX), group average and Ward are more robust.
