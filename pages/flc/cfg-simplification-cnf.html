Context-Free Grammars, Simplification & Chomsky Normal Form

Slides 292–341 (CFG, derivations, ambiguity, simplification, CNF) plus every related question from your five papers. The CFG-design questions (switch-case, do-while, function prototypes, declarations) are in section 7. Textbooks: Hopcroft–Motwani–Ullman (HMU), Introduction to Automata Theory, Languages, and Computation, 3rd ed.; Sipser, Introduction to the Theory of Computation; Aho et al. (Dragon Book).

1. CFG basics

  • Definition: G = (V, T, P, S): V = variables (non-terminals), T = terminals (V ∩ T = ∅), P = productions A → α with head A ∈ V and body α ∈ (V ∪ T)*, S = start variable. “Context-free” because replacing A by α never depends on the symbols around A (the α₁Aα₂ context).
  • Derivation ⇒ one step, ⇒* zero or more steps. Language L(G) = { w ∈ T* | S ⇒* w }. A language generated by some CFG is a context-free language (CFL).
  • Leftmost derivation: always expand the leftmost variable. Rightmost: always the rightmost. Parse tree: root S, interior nodes variables, leaves terminals (or ε), children of A read left to right are the body of the production used. The yield is the string.
  • Ambiguity: some string has two parse trees (equivalently two leftmost derivations). Slides: S → AS | a | b; A → SS | ab on abb; and E → E+E | E*E | (E) | x | y | z on x+y+z (groups either way). Fixing it: rewrite with one variable per precedence level (E→E+T|T; T→T*F|F; F→(E)|id) or add precedence/associativity rules. Inherent ambiguity exists for some CFLs.

Reading a grammar (slide 299)

S → AS | ε; A → A1 | 0A1 | 01. A generates 0i1j with 1 ≤ i ≤ j; S generates a sequence of A’s. So L = strings made of blocks of 0s each followed by at least as many 1s. Method: solve the inner variable first, then the one that uses it.

Why CFG? (slide 295)

Parsers (yacc, bison) are built from CFGs; XML formats are described by CFGs; CFGs handle nesting (balanced brackets, if-else) that regular expressions cannot. Every regular language is context-free, not vice versa.

Read: HMU Ch. 5 “Context-Free Grammars and Languages” (§5.1 Context-Free Grammars, §5.2 Parse Trees, §5.4 Ambiguity in Grammars and Languages); Sipser Ch. 2 §2.1 “Context-Free Grammars”; Dragon Book §4.2 “Context-Free Grammars”.

3. Simplifying a CFG

Goal: remove symbols and productions that do nothing, without changing the language (except possibly ε). Order matters: ε-productions → unit productions → useless symbols (removing ε or unit rules can create new useless symbols, never the other way round), and then CNF if asked.

A. Useless variables slides 306–314

X is useful if S ⇒* αXβ ⇒* w with w ∈ T*; otherwise useless. Remove in this order:

  1. Non-generating (cannot derive any terminal string). Mark every variable with a body of only terminals; repeat: mark A if some body consists of terminals and marked variables. Unmarked variables go; delete every production containing them.
  2. Non-reachable (not reachable from S). Mark S; repeat: if A is marked, mark every variable in A’s bodies. Delete the rest.

Slide example: S→AB|CA; A→a; B→BC|AB; C→aB|b. B is non-generating (every B-body contains B or C→aB, which needs B), so S→CA, A→a, C→b remain. Second example S→Aab|AB; A→a; B→bD|bB; C→A|B; D→a: C is unreachable, so it and its productions go.

B. ε-productions slides 315–320

  1. Nullable variables: A is nullable if A → ε, or A → X₁…Xₖ with every Xᵢ nullable (iterate until stable).
  2. Rewrite: for each production A → X₁…Xₖ, add every version obtained by deleting any subset of the nullable Xᵢ (but never add an empty body). Then delete all A → ε.

Slide pattern: A → X₁X₂X₃X₄ with X₁, X₃ nullable gives X₁X₂X₃X₄ | X₂X₃X₄ | X₁X₂X₄ | X₂X₄ (four versions, 2² for two nullable symbols). If S is nullable, the result keeps S → ε (ε ∈ L); if S appears in a body, introduce a new start S′ → S | ε first (Sipser’s approach).

C. Unit productions slides 321–323

A unit production is A → B (one variable). For each pair (A, B) with A ⇒* B using unit rules only, copy B’s non-unit bodies to A; then delete all unit productions. A cycle A → B → A just makes A and B interchangeable.

Slide example: S→A|Bb; A→C|a; B→aBa|b; C→aSa. Pairs: S⇒A⇒C. Result S → Bb | aSa | a; A → a | aSa; B → aBa | b; C → aSa (A and C are then unreachable and go in the useless step).

Read: HMU Ch. 7 “Properties of Context-Free Languages”, §7.1 “Normal Forms for Context-Free Grammars” (§7.1.1 Eliminating Useless Symbols, §7.1.2 Computing the Generating and Reachable Symbols, §7.1.3 Eliminating ε-Productions, §7.1.4 Eliminating Unit Productions).

4. Chomsky Normal Form

A grammar is in CNF if every production is A → BC (two variables) or A → a (one terminal), plus S → ε if ε ∈ L (then S must not appear in any body). Every CFL has a CNF grammar. Uses: CNF parse trees are binary, so any string of length n ≥ 1 needs exactly 2n − 1 derivation steps (n−1 binary + n terminal rules); the CYK parsing algorithm and many proofs (pumping lemma) rely on it.

Conversion procedure slides 328–341

  1. Simplify: remove ε-productions, unit productions, then useless symbols.
  2. Isolate terminals: in every body of length ≥ 2, replace each terminal a by a new variable Xₐ and add Xₐ → a. Bodies that are a single terminal stay.
  3. Binarize: a body A → B₁B₂…Bₙ with n ≥ 3 becomes A → B₁D₁; D₁ → B₂D₂; …; Dₙ₋₂ → Bₙ₋₁Bₙ.

Slide example: A → bCDeF → step 2 A → BCDEF, B → b, E → e → step 3 A → B D₁; D₁ → C D₂; D₂ → D D₃; D₃ → E F.

Slide class exercise (341): S→ε | ABBA; B→bCb; A→a; C→c

No unit or useless symbols; S → ε is kept (S not on any right side). Terminals: Xb → b. Binarize: S → A K₁; K₁ → B K₂; K₂ → B A; B → Xb K₃; K₃ → C Xb.

S → ε | A K1      K1 → B K2     K2 → B A
B → Xb K3         K3 → C Xb
A → a             C → c         Xb → b
Common slip: doing step 2 on bodies like a (a single terminal): leave them alone. Another: reusing one helper variable for two different pairs. Reuse is correct only when the pair is identical (e.g. both AS).
Read: HMU §7.1.5 “Chomsky Normal Form”; Sipser Ch. 2 §2.1 “Chomsky Normal Form” (a slightly different recipe: add a new start symbol first, then remove ε, units, then convert).

  4. Terminals: Xₐ → a. S → XₐA | AXₐ; A → XₐBB; B → AXₐ.

Fall 2024 and Spring 2023 (same simplified grammar)

Fall 2024: S→ASB; A→aAS|a|ε; B→SbS|A|bb. Spring 2023: S→ASB|SB; A→aAS|aS|a; B→SbS|A|ε|bb. Both reduce to the same grammar:

  3. Unit B → A: B → SbS | aAS | aS | a | bb.

7. Exam questions: CFG design with derivations

switch-case Sp25, Sp24 · 6 marks

S     → switch ( id ) { Cases Def }
Cases → Case Cases | Case
Case  → case num : Stmts break ;
Def   → default : Stmts break ; | ε
Stmts → Stmt Stmts | ε
Stmt  → id = num ;

Dummy code switch(x){ case 1: y=1; break; default: y=0; break; }, leftmost derivation:

S ⇒ switch ( id ) { Cases Def }
  ⇒ switch ( id ) { Case Def }                        (Cases → Case)
  ⇒ switch ( id ) { case num : Stmts break ; Def }
  ⇒ … case num : Stmt Stmts break ; Def               (Stmts → Stmt Stmts)
  ⇒ … case num : id = num ; Stmts break ; Def         (Stmts → ε)
  ⇒ switch ( id ) { case num : id = num ; break ; default : Stmts break ; }
  ⇒ … default : id = num ; break ; }                  [id=x,y; num=1,0]

do-while with nested statements Fa24

S     → do { Stmts } while ( Cond ) ;
Stmts → Stmt Stmts | ε
Stmt  → id = Expr ; | S
Cond  → Expr relop Expr
Expr  → Expr + Term | Term         Term → id | num

do { x = 0; do { y = x + 1; } while (y < 5); } while (x < 3); The outer S ⇒ do { Stmts } while ( Cond ) ; ⇒ Stmts ⇒ Stmt Stmts ⇒ (id = Expr ;) (Stmt Stmts) ⇒ the second Stmt ⇒ S (inner do-while) ⇒ do { Stmt } while ( Cond ) ; with Stmt ⇒ id = Expr ; (y = x + 1).

Function prototypes Sp23

P    → Type id ( Args )
Args → ε | List
List → Type id | Type id , List
Type → int | void | double

double name(double arg1, int arg2): P ⇒ Type id ( Args ) ⇒ double name ( List ) ⇒ double name ( Type id , List ) ⇒ double name ( double arg1 , Type id ) ⇒ double name ( double arg1 , int arg2 ).

Declarations, assignments, expressions Fa23

Prog → Stmt Prog | Stmt
Stmt → Decl | Assign | Print
Decl → Type id ;                 Type → int | float | string
Assign → id = Expr ;             Print → print ( id ) ;
Expr → Expr + Term | Expr - Term | Term
Term → Term * Factor | Term / Factor | Factor
Factor → id | num | str | ( Expr )

For int a; float b; a = 10; b = a * 2.5; (num covers 10 and 2.5): Prog ⇒ Stmt Prog ⇒ Decl Prog ⇒ Type id ; Prog ⇒ int a ; Prog … the last Stmt ⇒ Assign ⇒ id = Expr ; with Expr ⇒ Term ⇒ Term * Factor ⇒ Factor * Factor ⇒ id * num. The Expr/Term/Factor layering makes * bind tighter than + and the grammar unambiguous.

8. Mistakes & practice

  • Removing unit productions before ε-productions (ε-removal can create new unit rules).
  • Forgetting to keep S → ε when S is nullable (language changes).
  • Adding the “all nullable removed” body: if every symbol in a body is nullable, skip the empty version.
  • Removing a non-generating variable but leaving productions that mention it.
  • In CNF, mixing a terminal and variable in one body (A → aB is not CNF).

P1. Remove ε-productions: S → AB; A → aA | ε; B → bB | ε.

AnswerNullable A, B, S. S → AB | A | B | ε; A → aA | a; B → bB | b. Then units S → A, S → B: S → AB | aA | a | bB | b | ε.

P2. Remove unit and useless symbols: S → A | b; A → B | a; B → c.

AnswerS ⇒ A ⇒ B; so S → b | a | c; A → a | c; B → c. A and B are now unreachable, so the final grammar is S → a | b | c.

P3. CNF of S → aSb | ab.

AnswerS → Xa K | Xa Xb; K → S Xb; Xa → a; Xb → b.

P4. A CNF grammar derives a string of length 6. How many derivation steps?

Answer2n − 1 = 11 (5 rules of the form A → BC and 6 of the form A → a).
