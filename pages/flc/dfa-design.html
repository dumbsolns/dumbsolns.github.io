DFA Design & Regular Expressions → DFA

The bridge between the two topics: how to design a DFA from a language description or a regular expression, and every such question from your five papers (Q4d: “construct DFAs from the following regular expressions”, plus the Spring 2023 “draw a DFA for…”). Companion pages: Regular expressions (building REs) and Automata conversions (NFA → DFA, minimization). Textbooks: Hopcroft–Motwani–Ullman (HMU), Introduction to Automata Theory, Languages, and Computation, 3rd ed.; Sipser, Introduction to the Theory of Computation.

1. The design method

A DFA is (Q, Σ, δ, q₀, F) with exactly one move for every state and every symbol. The skill is deciding what each state remembers.

  1. Decide what must be remembered about the prefix read so far: progress through a fixed pattern, the last few symbols, a parity or a count mod n, or “already failed”.
  2. One state per distinct memory. The start state remembers “nothing yet” (ε).
  3. Mark final states: the memories for which the string read so far is in the language.
  4. Fill every transition. Anything that can never lead to acceptance goes to a dead (trap) state that loops on all symbols. Check every state has an arrow for every symbol.
  5. Test with ε, a short string that is accepted, and two that are rejected.
  6. Optionally minimize: states that behave the same on every future string can be merged (see the conversions page).
For an RE: read it left to right as a sequence of required pieces; draw the chain for the fixed parts, add loops for stars, and branch only where the RE has a union. Build the DFA directly when the RE is small, or first build an NFA and convert it.
Read: HMU Ch. 2 §2.2 “Deterministic Finite Automata” (definition, transition diagrams and tables, extended δ, the language of a DFA); Sipser Ch. 1 §1.1 “Finite Automata” (Designing finite automata, the “reader as automaton” idea).

A. “Ends with abba” over {a, b} Spring 2023

q₀ = no progress, q₁ = ends in a, q₂ = ends in ab, q₃ = ends in abb, q₄ = ends in abba (final). After each symbol move to the state for the longest suffix of the input that is a prefix of abba.

Explanations of the fall-backs: from q₃ on b the text ends in abbb, which has no useful suffix ⇒ q₀. From q₄ on a: abbaa ends in a ⇒ q₁; on b: abbab ends in ab ⇒ q₂. Test: abba ✓, aabba ✓, abbab ✗.

B. “Odd number of 0s or even number of 1s” over {0, 1} Spring 2023

Track both parities: state (p₀, p₁) with p₀ = parity of 0s, p₁ = parity of 1s. A 0 flips the first, a 1 flips the second. Start (e,e). Final when p₀ is odd or p₁ is even.

State01Final?
→ (e,e)(o,e)(e,o)yes (1s even)
(e,o)(o,o)(e,e)no
(o,e)(e,e)(o,o)yes
(o,o)(e,o)(o,e)yes (0s odd)

Only (e,o) is non-final: the language is every string except those with an even number of 0s and an odd number of 1s. For AND, only (o,e) would be final. This product idea (HMU §4.2.1 “Closure under intersection”) is how to combine any two conditions.

C. “No substring 00” (compare with the RE (1+01)*(ε+0))

A = last symbol not 0 (start), B = last symbol 0, D = dead (00 seen). A: 0→B, 1→A. B: 0→D, 1→A. D loops. Finals A, B. Each loop in the RE (1 and 01 from A back to A) is a path in the DFA.

D. Binary numbers divisible by 3 (mod-counting)

States = remainder r ∈ {0,1,2}; reading bit b maps r to (2r + b) mod 3. r₀: 0→r₀, 1→r₁; r₁: 0→r₂, 1→r₀; r₂: 0→r₁, 1→r₂. Start and final: r₀.

3. Regular expression → DFA

Two valid routes. Pick whichever the question allows:

  • Direct design: read the RE as a pattern (prefix, loop, suffix), then apply section 2. Fast for small REs; the answer is accepted as long as the DFA is complete and correct.
  • Systematic: RE → ε-NFA (Thompson construction, see the RE page) → remove ε / subset construction → minimize (see conversions page). Slower, always works.

Translate each RE operator into DFA shape: concatenation = chain; star = loop (return to the state before the starred part, or a state with the same future behaviour); union = branches that either end in finals or merge. (0+1)* in the middle is a state that loops on both symbols.

The “ends with” trap: for (0|1)*w the end of the string must be exactly w, so use fall-back arrows (section 2A). For w(0|1)* use an absorbing final state. For w(0|1)*w track the suffix only after the prefix is complete, so “abab” is the shortest string for ab(a|b)*ab, not “ab”.

5. DFA ⇄ regular expression: checking your answer

  • Describe a DFA in words: name what each state means, then read the final states. That sentence is the “language” you can turn into an RE with the pattern table on the RE page.
  • DFA → RE: state elimination (HMU §3.2.2). Example: the “ends with 01” DFA gives (0+1)*01.
  • Compare answers: two DFAs accept the same language iff their minimized forms are identical (HMU §4.4.2); useful for checking that your direct design matches the book answer.
  • Complement: to get “does not end with 01”, keep the same complete DFA and swap final and non-final states. This does not work on an NFA.
Read: HMU Ch. 3 §3.2.2 “Converting DFA’s to Regular Expressions by Eliminating States”, Ch. 4 §4.2.1–4.2.2 “Closure under complementation / intersection (product construction)”, §4.4.2 “Testing equivalence of regular languages”; Sipser Ch. 1 §1.1 “The regular operations”.

6. Mistakes & practice

  • Missing arrows: every state needs one arrow per symbol. Add the dead state instead of leaving blanks.
  • Making the last state of an “ends with” DFA absorbing (it must move on).
  • Letting the suffix of w(0|1)*w overlap the prefix.
  • Mixing up AND and OR in product constructions: check which pair-states are final.
  • Not marking the start state final when ε belongs to the language (e.g. 1*).

P1. DFA for even number of 0s and even number of 1s.

AnswerStates (p₀,p₁) with parities, start and only final state (e,e); 0 flips p₀, 1 flips p₁. Four states: (e,e) –0→ (o,e), –1→ (e,o), etc.

P2. DFA for strings over {0,1} that start with 0 and end with 1.

AnswerStart S –1→ D, S –0→ X (last symbol 0). X: 0→X, 1→Y*. Y*: 0→X, 1→Y*. Dead D loops. Four states; the string “0” is rejected because it ends in 0.

P3. How many states does the minimal DFA for “contains 101” need (alphabet {0,1})?

AnswerFour: q₀ (nothing), q₁ (1), q₂ (10), q₃ (101, final, absorbing). No dead state is needed because every state can still reach acceptance.

P4. Give a DFA for “does not end with 01”, starting from the DFA for “ends with 01”.

AnswerKeep the three-state DFA (A: 0→B,1→A; B: 0→B,1→C; C: 0→B,1→A) and make A and B final, C non-final.
