Pushdown Automata (PDA)

Slides 342–361: the stack, the 7-tuple, moves (⊢), acceptance, DPDA vs NPDA, and worked designs. Then every PDA question from your papers: Spring 2025 (wwᴿ, input 001100), Spring 2024 (w01wᴿ, input 100101), Spring 2023 (aⁿba²ⁿ, input aabaaaa), plus the theory questions. Textbooks: Hopcroft–Motwani–Ullman (HMU), Introduction to Automata Theory, Languages, and Computation, 3rd ed.; Sipser, Introduction to the Theory of Computation.

1. What a PDA is

  • A finite automaton + a stack (LIFO, unbounded). The stack gives it memory for counting and matching, which a DFA/NFA does not have. A PDA recognizes exactly the context-free languages.
  • Formal definition: P = (Q, Σ, Γ, δ, q₀, Z, F)
    • Q: finite set of states; Σ: input alphabet; Γ: stack alphabet (finite);
    • δ: transition function; q₀ ∈ Q: start state; Z ∈ Γ: initial stack symbol (bottom marker); F ⊆ Q: final states.
  • Transition function: δ(q, a, X) = { (p, γ), … } where a ∈ Σ ∪ {ε}, X ∈ Γ, p ∈ Q, γ ∈ Γ*. Meaning: in state q, reading input a (or no input if a = ε), with X on top of the stack: move to state p, pop X and push the string γ (leftmost symbol of γ becomes the new top).
  • Typical stack operations: push (p, AX) (γ longer than X), pop (p, ε), replace (p, Y), no change (p, X).
  • A move may consume input (a ∈ Σ) or be an ε-move (spontaneous). The move depends on the state, the next input symbol and the stack top; the stack top is always popped when the move is taken.

2. Instantaneous descriptions and acceptance

  • ID (instantaneous description): a snapshot (q, w, γ): current state, remaining input, stack contents (top on the left).
  • Turnstile: (q, aw, Xβ) ⊢ (p, w, γβ) if (p, γ) ∈ δ(q, a, X). ⊢* means zero or more moves. For an ε-move the input does not change.
  • Acceptance by final state: L(P) = { w | (q₀, w, Z) ⊢* (q, ε, γ), q ∈ F } (any stack).
  • Acceptance by empty stack: N(P) = { w | (q₀, w, Z) ⊢* (q, ε, ε) } (any state).
  • The two modes have the same power: any PDA of one kind can be converted to the other (HMU §6.2.3 and §6.2.4). In an exam say which mode you use, and use a bottom marker Z so you can detect an empty stack.
  • The input is accepted if some sequence of choices succeeds (nondeterminism); you only need to show one accepting computation.
How to write the IDs: start (q₀, whole string, Z); at every ⊢ change the state, drop the consumed symbol from the front of the input, and rewrite the stack top-first. Number or list every move; mark the ε-move that “guesses the middle”.

3. Design strategies, with transition tables

Stack alphabet Γ = {Z, …}; Z marks the bottom. The tables list δ(state, input, top) = (new state, string pushed).

A. Counting: aⁿbⁿ, n ≥ 1 (DPDA, final-state acceptance)

Push one A per a; pop one A per b; accept when only Z is left.

δ(q0, a, Z) = (q0, AZ)       δ(q0, a, A) = (q0, AA)
δ(q0, b, A) = (q1, ε)        δ(q1, b, A) = (q1, ε)
δ(q1, ε, Z) = (q2, Z)        F = {q2}
(q0,aabb,Z) ⊢ (q0,abb,AZ) ⊢ (q0,bb,AAZ) ⊢ (q1,b,AZ) ⊢ (q1,ε,Z) ⊢ (q2,ε,Z)  accept

Variant aⁿb²ⁿ: push AA per a and pop one A per b. Ratio questions are answered by changing the amount pushed.

B. Matching a reverse: wwᴿ over {0,1} (NPDA)

Push the first half; guess the middle with an ε-move; then pop-match the second half. Write a ∈ {0,1} and X ∈ {0, 1, Z}.

δ(q0, a, X) = (q0, aX)         push every symbol
δ(q0, ε, X) = (q1, X)          guess: the middle is here
δ(q1, a, a) = (q1, ε)          match and pop
δ(q1, ε, Z) = (q2, Z)          F = {q2}

C. Marker between: w01wᴿ (NPDA, because 0 and 1 also occur in w)

δ(q0, a, X) = (q0, aX)         push w
δ(q0, 0, X) = (q1, X)          guess: this 0 starts the marker 01
δ(q1, 1, X) = (q2, X)          marker 1
δ(q2, a, a) = (q2, ε)          match wᴿ
δ(q2, ε, Z) = (q3, Z)          F = {q3}

D. Ratio: aⁿ b a²ⁿ (push twice, pop once per a)

δ(q0, a, Z) = (q0, AAZ)   δ(q0, a, A) = (q0, AAA)     push two A per a
δ(q0, b, Z) = (q1, Z)     δ(q0, b, A) = (q1, A)        n = 0 allowed
δ(q1, a, A) = (q1, ε)     δ(q1, ε, Z) = (q2, Z)        F = {q2}

E. Comparing counts: equal numbers of a’s and b’s

The stack holds the surplus of whichever symbol is ahead (A for extra a’s, B for extra b’s); an opposite symbol cancels.

δ(q, a, Z) = (q, AZ)   δ(q, a, A) = (q, AA)   δ(q, a, B) = (q, ε)
δ(q, b, Z) = (q, BZ)   δ(q, b, B) = (q, BB)   δ(q, b, A) = (q, ε)
δ(q, ε, Z) = (f, Z)    F = {f}

For unequal counts, accept when the surplus is non-empty instead: after the input is read, an ε-move that sees A or B on top goes to the final state.

Recipe: (1) what must be remembered? count or sequence → stack; (2) where does the stack change? (3) is the switching point visible (a different symbol, a marker) or must it be guessed (ε-move, NPDA)? (4) how do I know it matched? Z reached. Then write the table, then trace one accepted and one rejected string.

4. Past-paper answers (Q4c, 6 marks)

Spring 2025: L = { wwᴿ | w ∈ {0,1}* }, input 001100

Use design B. Here w = 001 and wᴿ = 100. The stack is written top-first.

(q0,001100,Z)
⊢ (q0,01100,0Z)    push 0
⊢ (q0,1100,00Z)    push 0
⊢ (q0,100,100Z)    push 1
⊢ (q1,100,100Z)    ε-move: guess the middle
⊢ (q1,00,00Z)      read 1, pop 1
⊢ (q1,0,0Z)        read 0, pop 0
⊢ (q1,ε,Z)         read 0, pop 0
⊢ (q2,ε,Z)         ε-move: only Z left, accept

Rejected example: 0010 (odd/not a palindrome): the guess at any position leaves a mismatch or leftover symbols.

Spring 2024: L = { w01wᴿ | w ∈ (0+1)* }, input 100101

Use design C. Here w = 10, so the string splits as 10 · 01 · 01.

(q0,100101,Z)
⊢ (q0,00101,1Z)   push 1
⊢ (q0,0101,01Z)   push 0
⊢ (q1,101,01Z)    guess: this 0 is the marker’s 0
⊢ (q2,01,01Z)     marker’s 1
⊢ (q2,1,1Z)       read 0, pop 0
⊢ (q2,ε,Z)        read 1, pop 1
⊢ (q3,ε,Z)        accept

Spring 2023: L = { aⁿ b a²ⁿ | n ≥ 0 }, input aabaaaa

Use design D (n = 2: two a’s, then b, then four a’s).

(q0,aabaaaa,Z)
⊢ (q0,abaaaa,AAZ)    a: push AA
⊢ (q0,baaaa,AAAAZ)   a: push AA
⊢ (q1,aaaa,AAAAZ)    b: switch state
⊢ (q1,aaa,AAAZ)      a: pop
⊢ (q1,aa,AAZ)        a: pop
⊢ (q1,a,AZ)          a: pop
⊢ (q1,ε,Z)           a: pop
⊢ (q2,ε,Z)           accept

Fall 2024 (the language is hard to read in the scan)

The question gives input 00100. If the language is odd-length palindromes with a middle symbol, use design B with an extra ε-move that reads and discards the middle symbol: δ(q0, a, X) ∋ (q1, X). Trace: (q0,00100,Z) ⊢ (q0,0100,0Z) ⊢ (q0,100,00Z) ⊢ (q1,00,00Z) [read middle 1, no push] ⊢ (q1,0,0Z) ⊢ (q1,ε,Z) ⊢ (q2,ε,Z). If your copy of the paper shows a different language (for instance with a trailing fixed block), say so and send the line; the method (push first part, guess the boundary, match) stays the same.

5. PDA ⇄ CFG

CFG → PDA (one state, empty-stack acceptance): put the start symbol S on the stack; then
• for each production A → α: δ(q, ε, A) ∋ (q, α) (replace the variable by its body);
• for each terminal a: δ(q, a, a) = (q, ε) (match and pop).

Example S → aSb | ε on input aabb (stack top on the left):

(q,aabb,S) ⊢ (q,aabb,aSb) ⊢ (q,abb,Sb) ⊢ (q,abb,aSbb) ⊢ (q,bb,Sbb)
⊢ (q,bb,bb) ⊢ (q,b,b) ⊢ (q,ε,ε)   accept (empty stack)

This is a top-down (leftmost-derivation) parser: the stack of a predictive LL(1) parser works exactly this way, with a table choosing the production. A bottom-up shift-reduce parser uses the stack the other way round (push input, reduce a handle on top); that is the PDA for LR parsing.

PDA → CFG: variables [pXq] mean “from state p with X on top, reach q with X popped”; the construction is long and only needed for the proof (HMU §6.3.2).

Read: HMU §6.3 “Equivalence of PDA’s and CFG’s”, §6.4 “Deterministic Pushdown Automata”; Sipser Ch. 2 §2.2 (Theorem 2.20, equivalence with CFGs); Dragon Book §4.5 “Bottom-Up Parsing” (stack-based parsers).

6. Theory questions

“Describe a PDA. What are its advantages over a DFA/NFA?” Spring 2024, 4 marks

  • Description: finite control + input tape + stack; 7-tuple; moves use state, input symbol (or ε) and stack top; accepts by final state or empty stack.
  • Advantages: (1) unbounded memory through the stack, so it can count and match (aⁿbⁿ, balanced parentheses, wwᴿ); (2) recognizes all CFLs, a strictly larger class than the regular languages; (3) is the machine model behind parsing (nested structures in programming languages: expressions, blocks, if-else); (4) any DFA/NFA is a PDA that ignores its stack.
  • Limits: only one stack, so aⁿbⁿcⁿ and ww (copy language) are not CFLs; nondeterministic PDAs are more powerful than deterministic ones (wwᴿ needs a guess); simulation costs more than a DFA.

“Formally define DFA, NFA, PDA and ε-NFA…” Spring 2025, 4 marks

7. Mistakes & practice

  • Writing the stack with the top on the right in some IDs and on the left in others. Pick one (top-left) and keep it.
  • Forgetting the bottom marker Z, so “empty” cannot be detected.
  • Pushing in the wrong order: (p, AX) puts A above X.
  • Not showing the ε-move for the guessed middle (it counts as a move in the trace).
  • Claiming a DPDA exists for wwᴿ. It does not.

P1. PDA for aⁿb²ⁿ, n ≥ 0. Trace abb.

AnswerPush AA per a: δ(q0,a,Z)=(q0,AAZ), δ(q0,a,A)=(q0,AAA); on b switch and pop: δ(q0,b,A)=(q1,ε), δ(q1,b,A)=(q1,ε); δ(q0,ε,Z)=(q2,Z) for n = 0, δ(q1,ε,Z)=(q2,Z). Trace: (q0,abb,Z) ⊢ (q0,bb,AAZ) ⊢ (q1,b,AZ) ⊢ (q1,ε,Z) ⊢ (q2,ε,Z).

P2. Is { aⁿbⁿcⁿ | n ≥ 1 } accepted by a PDA?

AnswerNo. After matching a’s against b’s the stack is empty, so nothing is left to match the c’s. The language is not context-free.

P3. Which need a nondeterministic PDA: (i) aⁿbⁿ, (ii) wwᴿ, (iii) w c wᴿ, (iv) balanced parentheses?

AnswerOnly (ii). (i), (iii), (iv) are deterministic (the switch point is visible or no switch is needed).

P4. Convert S → 0S1 | 01 into a PDA and trace 0011.

Answerδ(q,ε,S) = {(q,0S1),(q,01)}; δ(q,0,0)=(q,ε); δ(q,1,1)=(q,ε). (q,0011,S) ⊢ (q,0011,0S1) ⊢ (q,011,S1) ⊢ (q,011,011) ⊢ (q,11,11) ⊢ (q,1,1) ⊢ (q,ε,ε).
