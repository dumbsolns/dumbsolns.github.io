Regular Expressions

Slides 32–38 (alphabets, strings, languages, RE rules) and 285–291 (lexical analysis), plus every “construct regular expressions for…” question from your five papers (Q4b). DFA design from a given regular expression (Q4d) comes in the next page on DFA design. Textbooks: Hopcroft–Motwani–Ullman (HMU), Introduction to Automata Theory, Languages, and Computation, 3rd ed.; Sipser, Introduction to the Theory of Computation; Dragon Book (Aho et al.).

1. Definition and notation

  • Alphabet Σ (finite, non-empty); string = finite sequence of symbols, |w| = its length, ε = empty string (|ε| = 0); Σ* = all strings over Σ including ε; Σ⁺ = all non-empty strings; language = any subset of Σ*. A regular expression describes a language; it is not itself a set.
  • Recursive definition (slides 36–37): the language L(E) of each expression:
ExpressionLanguageName
∅{ } (nothing)empty set
ε{ ε }empty string
a (a ∈ Σ){ a }symbol
E + F or E | FL(E) ∪ L(F)union
E F{ xy : x ∈ L(E), y ∈ L(F) }concatenation
E*zero or more strings of L(E) joinedKleene closure
(E)L(E)grouping
  • Precedence (highest first): star > concatenation > union. So ab*+c means (a(b*))+c. Union binds loosest, which is why 0+1 needs brackets inside bigger expressions: (0+1)*.
  • Your papers write union as + in some questions and | in others; they mean the same. In a lexer tool (lex/flex) + means “one or more”, not union, so say which convention you use.
  • Regular language: a language described by some regular expression (equivalently accepted by a DFA/NFA/ε-NFA). Regular languages are closed under union, concatenation and star, as the recursive definition shows.
Read: HMU Ch. 3 “Regular Expressions and Languages”, §3.1 “Regular Expressions” (§3.1.1 operators, §3.1.2 building RE’s, §3.1.3 precedence); Sipser Ch. 1 §1.3 “Regular Expressions”; Dragon Book §3.3 “Specification of Tokens”.

3. How to build a regular expression

  1. Understand the language: list 3–4 strings that belong and 3–4 that do not.
  2. Decompose: split into alternatives (union), sequence (concatenation) and repetition (star). Often the language is “anything, then the special part, then anything”: (0+1)* part (0+1)*.
  3. For “not containing X”, describe the allowed building blocks that never make X, then repeat them (see no-00 below).
  4. Test: run your accept strings and reject strings through the expression. Check ε and single-symbol strings explicitly.

Single-symbol trap: “starts and ends with the same symbol” includes the strings 0 and 1; forgetting them loses a mark. The same applies to “no 00” (ε, 0 must match; hence (ε+0)).

From a DFA to a regular expression: state elimination HMU §3.2.2

When a language is easier to see as an automaton, remove states one by one, merging paths into regular expressions on the edges. Example, “even number of 0s”: A (start, final) –1→ A, A –0→ B, B –1→ B, B –0→ A. Eliminate B: the route A → B → A reads 0 1* 0, so A’s loop becomes 1 + 01*0 and the answer is (1 + 01*0)*. (Equivalent to 1*(01*01*)*.)

Why x(x+yx)*(ε+y) works: after the first x, every y is immediately followed by an x (the yx unit) so no two y’s touch; the optional final y is allowed because nothing follows it. Test: xyxxy = x · yx · x · y ✓; xyy fails ✓.

5. Regular expression ⇄ automaton

RE → ε-NFA (McNaughton–Yamada–Thompson construction) Dragon Book §3.7.4

Build the machine by structure; each piece has one start state and one accepting state.

ExpressionMachine
εstart –ε→ accept
astart –a→ accept
R + Snew start with ε-edges into the starts of N(R) and N(S); ε-edges from both accepts into a new accept
R Saccept of N(R) joined (by ε, or merged) to start of N(S)
R*new start and accept; ε from new start to N(R)’s start and to the new accept; ε from N(R)’s accept back to N(R)’s start and to the new accept

Result: an ε-NFA with at most twice as many states as there are symbols and operators in the RE. Then apply the conversions of the automata conversions page (ε-removal, subset construction, minimization). This is the lexer pipeline from the compiler overview: RE → NFA → DFA.

Other directions

  • DFA → RE: state elimination (section 3), or the Rij(k) recurrence (HMU §3.2.1).
  • Hence RE, DFA, NFA and ε-NFA describe exactly the same class: the regular languages.
  • Languages that need a stack or counting (aⁿbⁿ, balanced parentheses) are not regular; use a CFG or PDA.
Read: HMU §3.2 “Finite Automata and Regular Expressions” (§3.2.3 converting regular expressions to automata); Sipser Ch. 1 §1.3 (Lemma 1.55 RE → NFA, Lemma 1.60 DFA → RE); Dragon Book §3.7.4.

6. Regular expressions in the lexical analyzer slides 285–291

Each token has a pattern written as a regular expression; the lexer matches the longest lexeme and returns <token, attribute>. Typical definitions:

TokenPatternExample lexemes
identifierletter (letter | digit | _)*swapped, arr, i2
integerdigit digit* (also written digit⁺)0, 400
real numberdigit⁺ . digit⁺2.5
relational op< | <= | == | != | > | >=<=
whitespace(blank | tab | newline)⁺ (discarded)
comment// (any char except newline)* (discarded)// If no two…
  • Keywords usually match the identifier pattern; the lexer looks them up in a reserved-word table (for, if, int).
  • Two rules decide ambiguity: take the longest match (<= not < then =), and if two patterns match equally, the earlier rule wins (keyword before identifier).
  • Extended notation in tools: [a-z] (class), R⁺ (one or more), R? (optional, = ε+R), R{n}. They are shorthand; the underlying languages are still regular.
Read: Dragon Book Ch. 3: §3.3.3 “Regular Expressions”, §3.3.5 “Extensions of Regular Expressions”, §3.4 “Recognition of Tokens”; Louden, Compiler Construction: Principles and Practice, Ch. 2 “Scanning”.

7. Mistakes & practice

  • Writing 0+1* when you mean (0+1)* (precedence: it means 0 or 1*).
  • Describing a contains language without (0+1)* on both sides.
  • Forgetting ε and one-symbol strings in “no pattern” or “starts/ends” languages.
  • Confusing R⁺ (at least one) with R* (zero or more).
  • Giving only an example string instead of the whole language; always test with at least one rejected string.

P1. Even number of 1s over {0,1}.

Answer0*(10*10*)*. Every 1 is paired with the next 1; zeros may appear anywhere. (Also (0*10*1)*0*.)

P2. No substring 11.

Answer(0+10)*(ε+1). Every 1 inside the string is followed by a 0, and a lone 1 is allowed at the end. Rejects 011, accepts 1010, 01, ε.

P3. Exactly two 0s.

Answer1*01*01*.

P4. Is (a+b)* = (a*b*)*?

AnswerYes, by the law (R+S)* = (R*S*)*. Both generate every string over {a,b}.

P5. Describe in words: (0+1)*0(0+1)(0+1).

AnswerStrings whose third symbol from the end is 0 (and length ≥ 3).
