1. Why FP-growth

Apriori generates candidate itemsets and rescans the data at every level. FP-growth compresses the transactions into a frequent pattern tree (FP-tree) after only two scans, then mines the tree with no candidate generation. It finds the same frequent itemsets as Apriori.

AprioriFP-growth
StrategyGenerate candidates, count, pruneBuild a tree, mine conditional databases
Database scansOne per levelTwo in total
CandidatesManyNone
CostCandidates and repeated scansMemory for the tree

2. The seven steps in your notes

StepName in your notesWhat you do
1Find support count of every itemCount the transactions containing each item. Exclude every item below the threshold. (Sorting is not needed at this stage.)
2Set with descending frequencyWrite the surviving items in descending count order, for example {K:5, E:4, M:3, O:3, Y:3}.
3Sort the original tableFor each transaction write the updated itemset (only surviving items), then the ordered itemset (same items in the order of step 2).
4Draw the treeStart from a Null root and insert the ordered transactions. A shared start only raises counts; a new item makes a new node.
5Conditional pattern baseFor each item, list the paths that lead to it (leaf up to the root, without the item) with the item’s count.
6Conditional frequent pattern treeIn each base, add up the count of every item (the “common: Σ count” in your notes). Keep items whose total is at least the threshold.
7Frequent itemsetsFor each item, combine it with every non-empty subset of its step-6 items, with the count.
  • Ties: M, O and Y all have count 3. Pick one order (for example alphabetical) and use it for every transaction; any fixed order gives the same final answer.
  • Order in step 5: your note says the paths go from leaf to root, but the order of items inside a path does not matter for the answer.
  • Duplicates: an item repeated inside one transaction (like “O, O” in T5) counts once.

5. How-to details

Building the tree without mistakes
  1. Work through the ordered transactions one at a time. Start at the root.
  2. For each item in the transaction, in order: if the current node already has a child with that item, move into it and add 1; otherwise create a new child with count 1 and move into it.
  3. Never reorder items inside a transaction and never skip an item, even if a branch already exists elsewhere in the tree.
  4. Keep a header table (item to all its nodes). It lets you find the nodes of an item for step 5 without searching.
  5. Final check: for every item, the counts of all its nodes add up to its step-1 count.
Conditional pattern bases and trees
  • Mine the items from the least frequent (bottom of the ordering) upwards. Its paths are short and each frequent pattern is found exactly once, as the suffix plus a pattern from its conditional tree. The item at the top of the ordering (K or I2) has no prefix paths, so it has no base.
  • For each node of the item, write the path from its parent up to (not including) the root, with the node’s count. Skip a node with an empty path.
  • For the conditional tree, total each item’s counts across all paths of the base. Keep items with a total of at least the threshold, and merge the paths that start the same way.
  • Step 7: take every non-empty subset of the kept items and add the suffix item. Each pattern’s count is the sum of the base paths that contain all the subset’s items, and it must still be at least the threshold.

7. Exam checklist and common mistakes

Layout to write in the exam
  1. State the threshold as a count (for example 60% of 5 = 3).
  2. Step 1: the count of every item, with the excluded ones marked. Step 2: the descending set.
  3. Step 3: the table with updated and ordered itemsets.
  4. Step 4: the tree, with counts on every node (and the header table if asked).
  5. Step 5: the conditional pattern base for every item except the top one.
  6. Step 6: the conditional FP-tree (the totals, and what was dropped).
  7. Step 7: the frequent itemsets for each item, then the final list including the single items.

Common mistakes

  • Leaving the below-threshold items in the ordered transactions.
  • Changing the tie order between transactions.
  • Counting a repeated item in one transaction twice.
  • Forgetting the single frequent items in the final answer.
  • Dropping the count of the suffix item’s node when copying a path into the base (each path carries the node’s count, not 1).
  • Using the wrong count for a pattern: use the smallest count on one path, or the sum over the paths that contain all the items.
