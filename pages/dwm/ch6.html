The big picture

transactions → [1] find frequent itemsets (expensive: Apriori, FP-growth, Eclat) ↓ [2] generate strong rules (cheap: s ⇒ l − s) ↓ [3] filter by interestingness (lift, χ², Kulc + IR)

Step 1 decides the running time of the whole task. Steps 2 and 3 are cheap or are filters.

6.1 Basic concepts

Definitions you must know exactly
  • Itemset = a set of items. A k-itemset has k items. A transaction T ⊆ I has a TID. T contains A if A ⊆ T.
  • Support count (absolute support, frequency) = number of transactions containing the itemset. Relative support = that count divided by |D|.
  • An itemset is frequent if its support meets min_sup. The set of frequent k-itemsets is Lk.
  • Rule A ⇒ B with A, B non-empty and A ∩ B = ∅.
support(A ⇒ B) = P(A ∪ B) = count(A ∪ B) / |D| confidence(A ⇒ B) = P(B | A) = count(A ∪ B) / count(A)

P(A ∪ B) means a transaction contains all items of both A and B, not “A or B”. A rule is strong if it meets both min_sup and min_conf. Support measures usefulness; confidence measures certainty.

Example 6.1: computer ⇒ antivirus software [support = 2%, confidence = 60%]. 2% of all transactions contain both; 60% of computer buyers also bought the software.

The two-step process: (1) find all frequent itemsets; (2) generate strong rules from them. Because step 2 is much cheaper, the overall performance depends on step 1.

Notes check: confidence is P(B|A) = count(A∪B)/count(A). The count of the left side is always in the denominator.

Han et al., Ch. 6, §6.1.1 “Market Basket Analysis: A Motivating Example”, §6.1.2 “Frequent Itemsets, Closed Itemsets, and Association Rules”; Zaki & Meira, Data Mining and Analysis, Ch. 8 “Itemset Mining”, §8.1 “Frequent Itemsets and Association Rules”; Tan et al., Introduction to Data Mining, chapter “Association Analysis: Basic Concepts and Algorithms”.

Why closed and maximal itemsets exist

If an itemset is frequent, every subset is frequent. A frequent itemset of length 100 therefore holds 2¹⁰⁰ − 1 ≈ 1.27 × 10³⁰ frequent itemsets (Eq. 6.5), too many to compute or store.

  • Closed: no proper superset has the same support count. A closed frequent itemset is closed and frequent.
  • Maximal (max-itemset): frequent, and no proper superset is frequent.

Relationship: maximal ⊆ closed ⊆ frequent. Every maximal frequent itemset is closed.

Example 6.2: D = {⟨a₁…a₁₀₀⟩, ⟨a₁…a₅₀⟩}, min_sup = 1. Closed: {a₁…a₁₀₀}:1 and {a₁…a₅₀}:2. Maximal: only {a₁…a₁₀₀}:1.

  • Closed sets are lossless. From C you can derive {a₂,a₄₅}:2 (subset of the count-2 closed set) and {a₈,a₅₅}:1 (it is only inside the count-1 set). Rule: support of any frequent itemset = the largest support among its closed supersets.
  • Maximal sets lose counts. You know {a₂,a₄₅} and {a₈,a₅₅} are frequent but not their supports.

Han et al., §6.1.2, Eq. (6.5) and Example 6.2; Zaki & Meira, Ch. 9 “Summarizing Itemsets”, §9.1 “Maximal and Closed Frequent Itemsets”. Notes: 17/09/26.

6.2 Frequent itemset mining methods

6.2.1 Apriori: the algorithm and the Apriori property

Apriori property: all non-empty subsets of a frequent itemset must also be frequent. Why: adding an item to an itemset cannot raise its support, so if I fails min_sup then I ∪ {A} fails too. This is antimonotonicity: if a set fails a test, all its supersets fail.

Level-wise search: find L₁ by one scan; use L₁ to find L₂; and so on until Lk is empty. Each Lk needs one full scan.

  1. Join step: Ck = Lk−1 ⋈ Lk−1. Two itemsets (sorted lexicographically) join if their first k−2 items are identical and the last items satisfy l₁[k−1] < l₂[k−1] (this avoids duplicates).
  2. Prune step: delete any candidate with a (k−1)-subset that is not in Lk−1.
  3. Scan D, count candidates, keep those with count ≥ min_sup as Lk.
L1 = frequent 1-itemsets(D) for (k = 2; L(k-1) not empty; k++) { Ck = apriori_gen(L(k-1)) // join + prune for each transaction t in D: count candidates contained in t Lk = { c in Ck : c.count >= min_sup } } return union of all Lk

Han et al., §6.2.1 “Apriori Algorithm: Finding Frequent Itemsets by Confined Candidate Generation”, Figure 6.4; Agrawal & Srikant (1994), the original Apriori paper (cited in the book as [AS94b]); Tan et al., sections “Frequent Itemset Generation” and “Candidate Generation and Pruning”.

6.2.2 Generating association rules from frequent itemsets

For each frequent itemset l, take every non-empty proper subset s and output s ⇒ (l − s) if count(l)/count(s) ≥ min_conf. Rules automatically meet min_sup because l is frequent. A k-itemset gives 2ᵏ − 2 candidate rules.

Example 6.4: X = {I1, I2, I5}, count 2.

{I1,I2} ⇒ I5 2/4 = 50% {I1,I5} ⇒ I2 2/2 = 100% {I2,I5} ⇒ I1 2/2 = 100% I1 ⇒ {I2,I5} 2/6 = 33% I2 ⇒ {I1,I5} 2/7 = 29% I5 ⇒ {I1,I2} 2/2 = 100%

With min_conf = 70%, only the 2nd, 3rd and 6th rules are output. Unlike classification rules, the right side can contain several items.

Faster rule generation (Exercises 6.3c and 6.5): since count(s′) ≥ count(s) for s′ ⊂ s, confidence(s′ ⇒ l − s′) ≤ confidence(s ⇒ l − s). So if a rule fails, every rule with a smaller left side from the same itemset fails too. In Example 6.4, {I1,I2} ⇒ I5 fails at 70%, so I1 ⇒ … and I2 ⇒ … can be skipped. Generate rules with the largest left side first and prune downward.

Han et al., §6.2.2 “Generating Association Rules from Frequent Itemsets”, Example 6.4; Exercises 6.3(c) and 6.5; Zaki & Meira, Ch. 8, §8.3 “Generating Association Rules”; Tan et al., section “Rule Generation”. Notes: 24/09/26.

6.2.3 Improving the efficiency of Apriori

Apriori’s two costs: many candidates (10⁴ frequent items give over 10⁷ candidate pairs) and repeated database scans. Five fixes from the book:

  • Hash-based counting: while computing L₁, hash every 2-itemset of each transaction into a bucket and count the buckets. A pair in a bucket with count below min_sup cannot be frequent. In Figure 6.5, with min_sup = 3 the buckets 0, 1, 3, 4 (counts 2) are dropped, so their pairs never enter C₂. Most useful at k = 2.
  • Transaction reduction: a transaction with no frequent k-itemset cannot contain a frequent (k+1)-itemset, so mark or drop it from later scans.
  • Partitioning (2 scans): split D into n non-overlapping partitions, each small enough for memory. Phase I: find local frequent itemsets in each partition (local threshold = min_sup × partition size). Phase II: one scan of D counts the union of all local frequent itemsets to get the global ones. This works because any globally frequent itemset must be locally frequent in at least one partition (if it were below the threshold in every partition, its total count would be below min_sup × |D|).
  • Sampling: mine a random sample S in memory with a lowered threshold to reduce misses, then verify the counts on the rest of D. One scan if no frequent itemset was missed, otherwise a second pass. Trades some accuracy for speed.
  • Dynamic itemset counting (DIC): D is split into blocks with start points; a new candidate can start counting at any start point, and its count-so-far acts as a lower bound. Fewer scans than Apriori.

Han et al., §6.2.3 “Improving the Efficiency of Apriori”, Figures 6.5 and 6.6; Exercise 6.3(d) (partitioning proof).

6.2.4 FP-growth: mining without candidate generation

Why: Apriori can generate huge candidate sets and rescans D. FP-growth uses divide and conquer: compress D into a frequent pattern tree (FP-tree) that keeps the itemset information, then mine conditional databases one frequent item at a time. It needs only two scans of D.

Build the tree (Example 6.5, min_sup = 2):

  1. Scan 1: count items. L = {I2:7, I1:6, I3:6, I4:2, I5:2} (descending support).
  2. Scan 2: sort each transaction’s frequent items in L order. T100 becomes I2, I1, I5. Insert into a tree with a “null” root. A shared prefix only increments counts; new items create new nodes.
  3. Keep a header table with node-links from each item to all its tree nodes.
null ├─ I2:7 │ ├─ I1:4 │ │ ├─ I5:1 │ │ ├─ I4:1 │ │ └─ I3:2 │ │ └─ I5:1 │ ├─ I4:1 │ └─ I3:2 └─ I1:2 └─ I3:2

Mine the tree: for each item, from the least frequent up, take its conditional pattern base (the prefix paths ending at that item, each with the item’s count), build the conditional FP-tree (drop items below min_sup), and append the item as a suffix to the patterns found.

For I5, I3 is dropped from its conditional tree because its count there is 1 < 2. If a conditional tree is a single path, all combinations of its nodes are patterns, each with the minimum count on the chosen nodes.

Why start from the least frequent item: its prefix paths are short and selective, and every frequent pattern is found exactly once, as a suffix plus a pattern from its conditional tree. FP-growth is reported to be about an order of magnitude faster than Apriori. If the tree is too big for memory, partition D into projected databases first.

Your class example (T1 {E,K,M,N,O,Y} … T5 {C,E,I,K,O,O}, threshold 3) is Exercise 6.6 in the book. Its tree is K:5 → E:4 (→ M:2 → O:1 → Y:1, and → O:2 → Y:1) plus K → M:1 → Y:1. Patterns: {K,Y:3}, {K,O:3}, {E,O:3}, {K,E,O:3}, {K,M:3}, {K,E:4}.

6.2.5 Vertical data format (Eclat)

Horizontal format is {TID : itemset} (Apriori, FP-growth). Vertical format is {item : TID set}. The support of an itemset is the size of its TID set, and a (k+1)-itemset’s TID set is the intersection of two k-itemset TID sets. No further database scans are needed after the first conversion.

I1 {T100,T400,T500,T700,T800,T900} I2 {T100,T200,T300,T400,T600,T800,T900} I3 {T300,T500,T600,T700,T800,T900} I4 {T200,T400} I5 {T100,T800} I1∩I2 = {T100,T400,T800,T900} (4) I1∩I3 = {T500,T700,T800,T900} (4) I1∩I5 = {T100,T800} (2) I2∩I3 = {T300,T600,T800,T900} (4) I2∩I4 = {T200,T400} (2) I2∩I5 = {T100,T800} (2) I1I4 = {T400} and I3I5 = {T800}: one transaction each, so infrequent Candidates (Apriori property): I1I2I3 → {T800,T900} (2); I1I2I5 → {T100,T800} (2)

Result: the same frequent itemsets as Apriori, found with 10 intersections for pairs.

Drawback and fix: TID sets can be long. A diffset stores only the difference: diffset({I1,I2},{I1}) = {T500, T700}, so support({I1,I2}) = 6 − 2 = 4. It helps most on dense data with long patterns.

6.2.6 Mining closed and max patterns (with a worked example)

Naive way: mine all frequent itemsets and delete non-closed ones. This is prohibitively costly (2¹⁰⁰ − 1 sets to reach one long pattern). Recommended: search for closed itemsets directly, using pruning:

  • Item merging: if every transaction containing X also contains Y (and no proper superset of Y), then X ∪ Y is closed and sets containing X without Y need not be searched. In Table 6.2, I5’s conditional database {{I2,I1},{I2,I1,I3}} always contains {I2,I1}, so {I5,I2,I1:2} is closed.
  • Sub-itemset pruning: if X is a proper subset of an already found closed set Y with the same support, X and its descendants cannot be closed.
  • Item skipping: if a local frequent item has the same support in header tables at several levels, prune it from the higher ones.

Closure checking: superset checking (built in when item merging is used) and subset checking (a pattern-tree indexed by last item and support).

Worked example: Table 6.1 at min_sup = 2. The 13 frequent itemsets (counts above) split as follows:

Closed (9): I1:6 I2:7 I3:6 {I1,I2}:4 {I1,I3}:4 {I2,I3}:4 {I2,I4}:2 {I1,I2,I3}:2 {I1,I2,I5}:2 Not closed: I4:2 (same as {I2,I4}), I5:2 and {I1,I5}:2 and {I2,I5}:2 (same as {I1,I2,I5}) Maximal (3): {I2,I4}:2 {I1,I2,I3}:2 {I1,I2,I5}:2

13 frequent → 9 closed → 3 maximal. Notice that {I1,I3}:4 is closed but not maximal (its superset I1I2I3 is frequent).

6.3 Which patterns are interesting?

6.3.1 Strong rules can be misleading (Example 6.7)

10,000 transactions: 6000 contain games, 7500 contain videos, 4000 contain both. With min_sup = 30% and min_conf = 60%, the rule game ⇒ video [support 40%, confidence 66%] is strong. But P(video) = 75%, higher than 66%, so buying games actually lowers the chance of buying videos. Confidence ignores the base rate of B. Interestingness can be subjective (user-judged) or objective (statistics-based); objective measures help weed out uninteresting rules.

Han et al., §6.3.1 “Strong Rules Are Not Necessarily Interesting”, Example 6.7.

6.3.2 Lift and χ² (Examples 6.8 and 6.9)

A correlation rule is A ⇒ B [support, confidence, correlation].

lift(A,B) = P(A ∪ B) / (P(A) P(B)) = P(B|A)/P(B) = conf(A⇒B)/sup(B) lift > 1 positively correlated; = 1 independent; < 1 negatively correlated

Game and video: lift = 0.40/(0.60 × 0.75) = 0.89 < 1, so negatively correlated.

χ² uses the 2 × 2 contingency table (expected values in brackets):

game ¬game Σrow video 4000 (4500) 3500 (3000) 7500 ¬video 2000 (1500) 500 (1000) 2500 Σcol 6000 4000 10,000 χ² = 500²/4500 + 500²/3000 + 500²/1500 + 500²/1000 = 555.6

χ² is large and the observed (game, video) count 4000 is below the expected 4500, so the correlation is negative, matching lift.

Han et al., §6.3.2 “From Association Analysis to Correlation Analysis”, Examples 6.8–6.9, Tables 6.6–6.7; Ch. 3, Eq. 3.1 (χ²). Notes: 22/07/26.

6.3.3 Null-invariant measures: all_conf, max_conf, Kulc, cosine, and IR

A null-transaction contains none of the itemsets being examined. A measure is null-invariant if null-transactions do not change its value. Lift and χ² are not null-invariant; the four below are.

all_conf(A,B) = sup(A∪B) / max{sup(A), sup(B)} = min{P(A|B), P(B|A)} max_conf(A,B) = max{P(A|B), P(B|A)} Kulc(A,B) = ½ (P(A|B) + P(B|A)) cosine(A,B) = sup(A∪B) / √(sup(A) × sup(B)) = √(P(A|B) × P(B|A)) IR(A,B) = |sup(A) − sup(B)| / (sup(A) + sup(B) − sup(A∪B))

All four range from 0 to 1 (higher means a closer relationship). IR (imbalance ratio) is 0 for a perfectly balanced pair and near 1 for a very skewed one.

Common mistakes and a quick exam checklist
  • Dividing by the wrong count: confidence divides by the count of the left side; support divides by |D|.
  • Counting an item twice within one transaction (a transaction contributes 1).
  • Forgetting the prune step: always check every (k−1)-subset against Lk−1 before scanning.
  • Joining itemsets that do not share the first k−2 items, which creates duplicates or invalid candidates.
  • Calling an itemset closed or maximal without comparing against all proper supersets. Closed looks at equal support; maximal looks at frequency.
  • FP-tree: forgetting to sort by descending support (and using one fixed tie-break order for every transaction).
  • Trusting confidence alone: report lift or Kulc when asked whether a rule is interesting.

Exam routine: (1) convert min_sup percentage to a count; (2) list C₁ and counts, then L₁; (3) join, prune, count for each level, stating why each pruned candidate was removed; (4) stop when Ck or Lk is empty; (5) for rules, list every non-empty proper subset and its confidence, then mark the strong ones.
