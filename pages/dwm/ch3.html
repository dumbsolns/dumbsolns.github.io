3.1 Overview: why preprocess?

3.1.1 Data quality (six dimensions) and 3.1.2 the major tasks

Data have quality if they satisfy the requirements of their intended use. The same data can be good for one user and bad for another: a marketing analyst may be happy with 80% accurate addresses for a mailing, while a sales manager finds them inaccurate.

DimensionMeaning, with the book’s example
AccuracyCorrect values. Causes of errors: faulty instruments, entry errors, transmission errors, users giving false values (the default “January 1” birthday, called disguised missing data), duplicates.
CompletenessAttributes and values present (for example the “on sale” flag was never recorded).
ConsistencyNo discrepancies in codes or formats (department codes, date formats).
TimelinessData available when needed. Month-end sales are incomplete until late records arrive, which delays bonuses.
BelievabilityHow much users trust the data, even after past errors were fixed.
InterpretabilityHow easily the data are understood (obscure accounting codes).

Four major tasks: cleaning (fill missing values, smooth noise, identify outliers, resolve inconsistencies); integration (merge databases, cubes or files; avoid redundancy); reduction (smaller representation with the same or almost the same results: dimensionality and numerosity reduction); transformation (normalization, discretization, concept hierarchies). Normalization matters for distance-based methods: unnormalized annual salary would outweigh age.

Han et al., Ch. 3 “Data Preprocessing”, §3.1.1 “Data Quality: Why Preprocess the Data?”, §3.1.2 “Major Tasks in Data Preprocessing”, Figure 3.1; Tan et al., Introduction to Data Mining, chapter “Data”, section “Data Preprocessing”. Notes: 16/07/26.

3.2 Data cleaning

3.2.1 Missing values: six methods and when to use each
  1. Ignore the tuple: usually when the class label is missing. Poor unless several attributes of the tuple are missing; it wastes the other values.
  2. Fill in manually: too slow for large data.
  3. Global constant (“Unknown”, −∞): simple, but the miner may treat “Unknown” as an interesting concept.
  4. Attribute mean or median: use the mean for a symmetric distribution and the median for a skewed one (income mean $56,000 in the book’s example).
  5. Mean or median of the same class: for example the mean income of customers in the same credit-risk class; use the median if the class is skewed.
  6. Most probable value: predict using regression, a Bayesian formula or a decision tree built from the other attributes. Popular because it uses the most information and best preserves relationships between attributes.

Methods 3 to 6 bias the data, because the filled value may be wrong. A missing value is not always an error: a driver’s licence number is blank for non-drivers. Forms should allow “not applicable”, and every attribute should have null rules.

Han et al., §3.2.1 “Missing Values”. Notes: 16/07/26.

3.2.2 Noisy data: binning, regression, outlier analysis (with numbers)

Noise is random error or variance in a measured variable. Smoothing methods:

Binning smooths a sorted value using its “neighbourhood”, so it is local smoothing. Equal-frequency bins hold the same number of values; equal-width bins span the same range. Larger bin width means stronger smoothing.

Sorted price: 4, 8, 15, 21, 21, 24, 25, 28, 34 Bin 1: 4, 8, 15 Bin 2: 21, 21, 24 Bin 3: 25, 28, 34 By bin means: 9, 9, 9 22, 22, 22 29, 29, 29 By bin medians: 8, 8, 8 21, 21, 21 28, 28, 28 By bin boundaries: 4, 4, 15 21, 21, 24 25, 25, 34 (boundaries: each value moves to the closer of the bin’s min or max)

Regression conforms values to a function. Linear regression fits y = wx + b by least squares: w = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)², b = ȳ − w·x̄ (standard formulas). Example: x = 1, 2, 3, 4 and y = 2, 4, 5, 8 give x̄ = 2.5, ȳ = 4.75, w = 9.5/5 = 1.9, b = 0, so the smoothed y values are 1.9, 3.8, 5.7, 7.6.

Outlier analysis: cluster the values; those outside every cluster may be outliers (Chapter 2’s IQR rule and boxplots also help).

Exam note from your class: in an exam, replace all values in each bin (do not leave the original values). Binning is also used for discretization (Section 3.5).

Han et al., §3.2.2 “Noisy Data”, Figure 3.2, Figure 3.3. Notes: 20/07/26.

3.2.3 Data cleaning as a process

Two steps that iterate: discrepancy detection and data transformation to fix what was found.

  • Discrepancy sources: poorly designed forms with optional fields, human error, deliberate errors, data decay (old addresses), inconsistent codes and formats, instrument errors, system errors, and integration.
  • Use metadata (type, domain, acceptable values) plus basic statistics (mean, median, mode, range, standard deviation; values more than two standard deviations from the mean may be outliers). Watch for inconsistent date formats and field overloading (new definitions squeezed into unused bits).
  • Rules to check: unique rule (all values different); consecutive rule (no gaps and all unique, like check numbers); null rule (how blanks, “?” or “don’t know” are stored).
  • Tools: data scrubbing (domain knowledge, parsing, fuzzy matching), data auditing (discover rules and find violations), data migration (simple transforms such as “gender” → “sex”), ETL tools (GUI-specified transforms). Interactive tools such as Potter’s Wheel let users build transformations step by step and undo mistakes.

The process is error-prone: a typo like “20010” in a year field may only appear after all dates are converted to one format, so several iterations are normal. Keep updating the metadata.

Han et al., §3.2.3 “Data Cleaning as a Process”.

3.3 Data integration

3.3.1, 3.3.3, 3.3.4 Entity identification, duplicates and value conflicts
  • Entity identification problem: matching equivalent entities across sources (does customer_id equal cust_number?). Use metadata (name, meaning, type, range, null rules), and check that functional dependencies and referential constraints match. Example: a discount applied to the whole order in one system but to each line item in another.
  • Tuple duplication: duplicates, often from denormalized tables, can become inconsistent when only some copies are updated (the same purchaser with two addresses).
  • Data value conflicts: different representation, scale or encoding (metric vs imperial; currencies, taxes and services in hotel prices; grading schemes A+ to F versus 1 to 10) or a different abstraction level (sales of one branch versus a whole region).

Han et al., §3.3.1 “Entity Identification Problem”, §3.3.3 “Tuple Duplication”, §3.3.4 “Data Value Conflict Detection and Resolution”.

3.3.2 Redundancy and correlation: the χ² test (Example 3.1)

An attribute is redundant if it can be derived from another (annual revenue from monthly revenue). Naming inconsistencies also cause redundancy. For nominal data use the χ² test, for numeric data use the correlation coefficient and covariance.

χ² = Σ (o − e)² / e e(i,j) = count(A = aᵢ) × count(B = bⱼ) / n degrees of freedom = (r − 1)(c − 1)

H₀: A and B are independent. If χ² exceeds the critical value at the chosen significance level, reject H₀: the attributes are statistically correlated. The cells that contribute most are those where the observed count differs most from the expected. In every row and column the expected values sum to the observed totals (a good check).

Example 3.1 (1500 people, gender vs preferred reading):

male female total fiction 250 (90) 200 (360) 450 non-fiction 50 (210) 1000 (840) 1050 total 300 1200 1500 e(male, fiction) = 300 × 450 / 1500 = 90 χ² = 160²/90 + 160²/210 + 160²/360 + 160²/840 = 284.44 + 121.90 + 71.11 + 30.48 = 507.93 df = 1; critical value at 0.001 = 10.828

507.93 > 10.828, so reject independence: gender and preferred reading are strongly correlated.

Class notes say the correlation is stronger when χ² is much larger than the table value, and that the “degree of freedom” has no deeper meaning here: you just read the table for (r − 1)(c − 1). Your past paper (S25 1a) uses exactly this method.

Han et al., §3.3.2 “Redundancy and Correlation Analysis”, Eqs. (3.1)–(3.2), Example 3.1, Table 3.1; Zaki & Meira, Data Mining and Analysis, Ch. 3 “Categorical Attributes” (bivariate analysis; check the section against your edition). Notes: 22/07/26, 23/07/26.

3.3.2 Correlation coefficient and covariance (Example 3.2)
r(A,B) = Σ (aᵢ − Ā)(bᵢ − B̄) / (n σA σB) = Cov(A,B) / (σA σB), −1 ≤ r ≤ +1 Cov(A,B) = E[(A − Ā)(B − B̄)] = E(A·B) − Ā·B̄
  • r > 0: positively correlated (higher means more redundancy); r = 0: no linear correlation; r < 0: negatively correlated.
  • Correlation does not imply causality: hospitals and car thefts are both driven by population.
  • Covariance gives the direction (sign) only; its size depends on units. Correlation also shows strength.
  • Independent attributes have covariance 0, but covariance 0 does not imply independence, except under extra assumptions (such as multivariate normal data).
  • Variance is the covariance of an attribute with itself.

Example 3.2 (stock prices at five time points):

AllElectronics: 6, 5, 4, 3, 2 mean 4 HighTech: 20, 10, 14, 5, 5 mean 10.8 Cov = (6×20 + 5×10 + 4×14 + 3×5 + 2×5)/5 − 4 × 10.8 = 50.2 − 43.2 = 7

Positive covariance: the prices rise together. Computed here: σ₁ = 1.414, σ₂ = 5.706, so r = 7/(1.414 × 5.706) = 0.867.

n or n − 1 does not change r, as long as you use the same one in the covariance and in both standard deviations. This is why your Fall 2024 answer (r = 0.965, using n − 1) is valid.

Han et al., Eqs. (3.3)–(3.6), Example 3.2, Table 3.2. Notes: 23/07/26.

3.4 Data reduction

3.4.1 Overview: dimensionality vs numerosity, lossless vs lossy
  • Dimensionality reduction reduces the number of attributes: wavelet transforms and PCA (project onto a smaller space), attribute subset selection (remove irrelevant, weak or redundant attributes), attribute construction.
  • Numerosity reduction replaces the data by a smaller representation: parametric (regression, log-linear models: store only parameters, plus outliers) or nonparametric (histograms, clustering, sampling, data cube aggregation).
  • Lossless reconstruction is exact; lossy gives only an approximation. The time spent reducing must not erase the time saved in mining.

Han et al., §3.4.1 “Overview of Data Reduction Strategies”. Notes: 16/07/26.

3.4.2 Discrete wavelet transform (class method, worked and reconstructed)

DWT turns a vector X into a vector X′ of wavelet coefficients of the same length. It helps reduction because the coefficients can be truncated: keep only the strongest, set the rest to 0, and the result is sparse. It also removes noise without smoothing out the main features, and it needs less space than the discrete Fourier transform for the same accuracy.

Book procedure: (1) length must be a power of 2 (pad with zeros); (2) apply a smoothing function (sum or average) and a weighted difference (detail); (3) apply both to pairs (x₂ᵢ, x₂ᵢ₊₁), giving two vectors of length L/2 (low and high frequency); (4) recurse on the smoothed vector; (5) selected values become the coefficients. A fast DWT is O(n); the matrix used is orthonormal. Common families: Haar-2, Daubechies-4, Daubechies-6.

Your class version (average and half-difference), S25 1c: X = 14, 12, 10, 8, 4, 6 padded to 8 values:

X = 14, 12, 10, 8, 4, 6, 0, 0 Avg₁ = 13, 9, 5, 0 Diff₁ = (a−b)/2 = 1, 1, −1, 0 Avg₂ = 11, 2.5 Diff₂ = 2, 2.5 Avg₃ = 6.75 Diff₃ = 4.25 X′ = [6.75 | 4.25 | 2, 2.5 | 1, 1, −1, 0] (coarse, then details, coarse to fine)

Reconstruction (inverse): a = avg + diff, b = avg − diff. From 6.75 and 4.25: [11, 2.5]; then [13, 9, 5, 0]; then [14, 12, 10, 8, 4, 6, 0, 0], exact.

Lossy compression (threshold): keep only coefficients with |c| ≥ 2 and set the level-1 details (1, 1, −1, 0) to 0. Reconstruct: [13, 13, 9, 9, 5, 5, 0, 0]. Each value is within 1 of the original, using 4 stored coefficients instead of 8.

Scales differ between books. The book’s Haar-2 uses factors of 1/√2 so the matrix is orthonormal; your class uses 1/2. Use the class version in exams and state it.

Han et al., §3.4.2 “Wavelet Transforms”, Figure 3.4; Zaki & Meira, Ch. 7 “Dimensionality Reduction” (for PCA; wavelets are covered in signal-processing texts). Notes: 27/07/26, 06/08/26.

3.4.3 Principal components analysis (theory plus both worked examples)

PCA (the Karhunen–Loève method) finds k orthonormal vectors (principal components) that best represent n-dimensional data, k ≤ n. Unlike attribute subset selection, which keeps a subset of the original attributes, PCA combines attributes into new ones. It handles sparse and skewed data, and the components can be inputs to regression and clustering.

Book procedure: normalize; compute k orthonormal vectors; sort by decreasing significance (PC1 has the most variance); drop the weak components. The more components you keep, the better the reconstruction.

Math steps (class method):

  1. Normalize with z-scores: z = (x − x̄)/σ.
  2. Covariance matrix C = [[Var(x), Cov(x,y)], [Cov(y,x), Var(y)]] of the normalized data.
  3. Eigenvalues: solve |C − λI| = 0. Each λ is the variance along its component. The loadings can never all be zero (v = 0 is excluded).
  4. Eigenvectors: for each λ solve (C − λI)v = 0, then scale to unit length.
  5. Sort by λ; PC1 has the largest. Variance explained = λᵢ / Σλ. Keep the top k.
  6. Project: component score = z · v.

Class example (hours studied 2–6, exam marks 1–5): z = −1.265, −0.632, 0, 0.632, 1.265 for both (σ with n − 1 = 1.581).

C = [1 1; 1 1] (the notes get 0.992 ≈ 1 from rounded z-values; exactly 1) |C − λI| = (1−λ)² − 1 = λ² − 2λ = λ(λ − 2) = 0 → λ = 2 (PC1), λ = 0 (PC2) λ = 2: [−1 1; 1 −1]v = 0 → v₁ = v₂ → v = [1/√2, 1/√2] λ = 0: v = [1/√2, −1/√2] PC1 scores = (z₁ + z₂)/√2 = −1.789, −0.894, 0, 0.894, 1.789 (variance 2) PC2 scores = 0 for every student (variance 0) PC1 explains 2/(2 + 0) = 100% of the variance

Fall 2024 1b (Quiz 6, 14, 16, 20; Assignment 5, 10, 15, 20): r = 110/√(104 × 125) = 0.965, so C = [[1, 0.965],[0.965, 1]], λ = 1 ± 0.965 = 1.965 and 0.035, vectors [1,1]/√2 and [1,−1]/√2. PC1 explains 98.2%.

For any 2 × 2 correlation matrix [[1, r],[r, 1]]: λ = 1 ± r, with eigenvectors [1,1]/√2 and [1,−1]/√2. This is a quick check for exam answers.

PCA vs DWT (book): PCA is better for sparse data; wavelets suit data of high dimensionality.

Han et al., §3.4.3 “Principal Components Analysis”, Figure 3.5; Zaki & Meira, Ch. 7 “Dimensionality Reduction”, §7.2 “Principal Component Analysis”. Notes: 27/07/26, 29/07/26.

3.4.4 Attribute subset selection (and attribute construction)

Goal: a minimum set of attributes whose class distribution is as close as possible to that of the full set. For n attributes there are 2ⁿ subsets, so heuristic greedy methods are used (best local choice at each step). “Best” and “worst” come from significance tests (assuming independent attributes) or measures such as information gain.

  • Stepwise forward selection: start from an empty set; at each step add the best remaining attribute; stop when the measure no longer improves. Book example: {} → {A1} → {A1, A4} → {A1, A4, A6}.
  • Stepwise backward elimination: start from all attributes; remove the worst each step. Book example: {A1…A6} → {A1, A3, A4, A5, A6} → {A1, A4, A5, A6} → {A1, A4, A6}.
  • Combination: at each step pick the best attribute for the reduced set E and remove the worst from the remaining set A.
  • Decision tree induction: build a tree; the attributes that appear in it are the reduced subset, the others are treated as irrelevant.

Attribute construction adds derived attributes (area from height and width) that expose relationships between attributes.

Your notes explain why the combination method helps: if A is the best single attribute but {A, C, D} is the best subset, a pure backward search may remove A early, while the combination keeps A and removes B.

Han et al., §3.4.4 “Attribute Subset Selection”, Figure 3.6; Tan et al., chapter “Data”, section “Feature Subset Selection”. Notes: 17/08/26.

3.4.5–3.4.7 Regression and log-linear models, histograms, clustering

Parametric (3.4.5). Linear regression: y = wx + b, coefficients by least squares; multiple regression uses two or more predictors. Log-linear models approximate discrete multidimensional probability distributions, so a high-dimensional space can be built from lower-dimensional ones; they scale to about 10 dimensions, while regression can be heavy in high dimensions. Regression handles skewed data exceptionally well.

Histograms (3.4.6). Buckets partition the attribute’s distribution. Singleton buckets hold one value (good for high-frequency outliers); otherwise buckets are ranges. Equal-width buckets have the same range; equal-frequency buckets hold roughly the same number of values. They approximate sparse, dense, skewed and uniform data, and multidimensional histograms (about up to five attributes) capture dependencies.

Example 3.3 (52 prices, rounded dollars), equal-width $10 buckets: 1–10 holds 13 values, 11–20 holds 25, 21–30 holds 14 (counts from the book’s list).

Clustering (3.4.7). Replace the data by cluster representations (a centroid and a diameter, the maximum distance between two objects, or the average distance to the centroid). Works well for distinct clusters, poorly for smeared data.

Han et al., §3.4.5 “Regression and Log-Linear Models: Parametric Data Reduction”, §3.4.6 “Histograms”, Example 3.3, Figures 3.7–3.8, §3.4.7 “Clustering”.

3.4.8 Sampling: four methods and their cost

Represent N tuples by a random sample of s tuples.

MethodHowNote
SRSWORDraw s of N; each tuple has probability 1/N; no tuple twiceUnbiased, simple
SRSWREach drawn tuple is recorded and put backDuplicates possible
Cluster sampleGroup tuples into M disjoint clusters (such as disk pages), take an SRS of s clustersCheap; may miss whole classes
Stratified sampleSplit D into strata (age groups), take an SRS from eachRepresentative for skewed data; the smallest group is still represented

Advantages: the cost is proportional to the sample size s (not N), so sampling can be sublinear in N; for fixed s the cost grows only linearly with the number of dimensions, while histograms grow exponentially. Sampling is mostly used to estimate aggregate queries (the central limit theorem gives a sufficient sample size), and it supports progressive refinement by increasing s.

3.4.9 Data cube aggregation

Aggregate data to the level needed. The book’s example: AllElectronics quarterly sales rolled up to annual sales. For 2008: Q1 $224,000 + Q2 $408,000 + Q3 $350,000 + Q4 $586,000 = $1,568,000; the aggregated table shows 2008 $1,568,000, 2009 $2,356,000, 2010 $3,594,000. The result is smaller yet keeps all information needed for the annual analysis.

A data cube stores multidimensional aggregates. The base cuboid is the lowest level and should be a useful entity (sale, customer); the apex cuboid is one grand total; cuboids form a lattice. Use the smallest cuboid that answers the task (Chapter 4 covers this in depth).

Han et al., §3.4.9 “Data Cube Aggregation”, Figures 3.10–3.11. Notes: see Chapter 4 deep dive.

3.5 Data transformation and discretization

3.5.1–3.5.2 Strategies and normalization (with ranges)

3.5.3–3.5.5 Discretization methods

Discretization replaces numeric values by interval labels (0–10, 11–20) or concept labels (youth, adult, senior); it is also a form of data reduction. Supervised methods use class information; unsupervised do not. Top-down (splitting) starts by finding split points; bottom-up (merging) starts with all values as potential split points and merges.

MethodTypeIdea
BinningUnsupervised, top-downEqual-width or equal-frequency bins; replace by bin label; sensitive to the number of bins and to outliers
Histogram analysisUnsupervisedEqual-width or equal-frequency buckets, applied recursively to build a hierarchy
Cluster analysisUnsupervisedCluster the values (splitting or merging); each cluster is a node of the hierarchy
Decision tree analysisSupervised, top-downChoose the split point with minimum entropy, so partitions are as pure in class as possible
ChiMerge (correlation)Supervised, bottom-upStart with each distinct value as an interval; merge adjacent intervals with the lowest χ² (similar class distributions) until a stopping criterion is met

3.5.6 Concept hierarchy generation for nominal data

Four methods:

  1. Order attributes at the schema level (street < city < province_or_state < country).
  2. Explicit grouping of part of a hierarchy ({Alberta, Saskatchewan, Manitoba} ⊂ prairies Canada).
  3. Attribute set without an ordering: order by the number of distinct values; the attribute with the most distinct values sits at the lowest level. Example 3.7: country (15) < province_or_state (365) < city (3567) < street (674,339). Not foolproof: 20 years, 12 months and 7 days of the week would wrongly put days of the week at the top.
  4. Partial set of attributes: semantically linked attributes are pinned together, so naming city drags in street, province_or_state and country (Example 3.8); users may drop some.

Han et al., §3.5.6 “Concept Hierarchy Generation for Nominal Data”, Examples 3.7–3.8, Figure 3.13.

Common mistakes and formula sheet
  • Forgetting to pad the DWT input to a power of 2, or mixing the 1/2 (class) and 1/√2 (book) conventions.
  • Using min-max with a new value outside the original range (out-of-bounds).
  • Leaving original values in a bin instead of replacing all of them.
  • Reading the χ² table with the wrong degrees of freedom (use (rows − 1)(columns − 1), not n − 1).
  • Concluding causation from correlation, or independence from zero covariance.
  • Skipping normalization before PCA: the attribute with the largest scale dominates PC1.
  • Calling PCA “attribute subset selection”: PCA creates new attributes; subset selection keeps original ones.
