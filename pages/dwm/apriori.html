1. The process in your notes

Apriori finds frequent itemsets and their frequencies. It does not produce association rules; that is a second, separate step (section 4). You build two kinds of table at each level k: Ck (candidates) and Lk (frequent itemsets).

StepTableWhat you writeCheck
1C₁ (v1)List the single items: I1, I2, I3, …Every distinct item appears once
2C₁ (v2)Add a support count column: how many transactions contain each itemCounts are per transaction (an item twice in one transaction counts once)
3L₁Keep only items whose count is at least the threshold; delete the restThreshold given as a percentage? Convert to a count first
4C₂ (v1)Join: combine each itemset of L₁ with each other item of L₁. Then apply the Apriori theorem: delete any candidate that has a subset not in L₁Show all versions: the joined list, then the list after deletion
5C₂ (v2)Count each surviving candidate in the transactionsOnly survivors are counted; deleted ones never reach v2
6L₂Keep candidates with count ≥ thresholdIf L₂ is empty, stop
7RepeatJoin Lk−1 to get Ck (v1), prune, count (v2), filter to LkStop when Ck or Lk is empty

How to join. The book joins Lk−1 with itself: two itemsets (items kept in sorted order) join if their first k−2 items are identical and their last items differ, which creates each candidate once. Your notes describe the same idea as extending each itemset of Lk−1 with an item from L₁. Both give the same Ck after the pruning check.

The Apriori theorem (the pruning check). Every non-empty subset of a frequent itemset is frequent. So a candidate with any (k−1)-subset missing from Lk−1 cannot be frequent: delete it before counting. Write the reason next to the deleted candidate, for example “I2I3I4 removed, because I3I4 is not in L₂”.

Notes check: the margin note on your C₂ page says the table “should be v2 but Apriori theorem”. Read it this way: C₂ (v1) is the joined list, and after the theorem removes candidates, the counted table is C₂ (v2). At level 2 nothing can be removed (all single items in L₁ are frequent), so v1 and v2 hold the same pairs.

Han, Kamber & Pei, Data Mining: Concepts and Techniques, 3rd ed., Ch. 6 “Mining Frequent Patterns, Associations, and Correlations: Basic Concepts and Methods”, §6.2.1 “Apriori Algorithm: Finding Frequent Itemsets by Confined Candidate Generation” (Figure 6.4, Example 6.3). Notes: 23/09/26.

4. From frequent itemsets to rules (your 24/09 notes)

Generate and filter the rules

Rules come after Apriori, from the frequent itemsets it found. Your notes: take the highest (largest) frequent itemsets, take subsets, and for every combination write {subset} ⇒ {itemset − subset} (the remaining items). All rules from one itemset have the same support but different confidence, so filter with confidence.

support(A ⇒ B) = count(A ∪ B) / total transactions confidence(A ⇒ B) = count(A ∪ B) / count(A) (the count of the left side, the subset, is the denominator) Steps for one frequent itemset l: 1. list every non-empty proper subset s (a k-itemset gives 2^k − 2 rules) 2. write the rule s ⇒ (l − s) 3. confidence = count(l) / count(s) (look count(s) up in your C/L tables) 4. keep the rule if confidence ≥ min_conf

Example 6.4 (min_conf = 70%): l = {I1, I2, I5}, count 2. Counts of the subsets come from your tables: I1 6, I2 7, I5 2, I1I2 4, I1I5 2, I2I5 2.

{I1,I2} ⇒ I5 2/4 = 50% no {I1,I5} ⇒ I2 2/2 = 100% YES {I2,I5} ⇒ I1 2/2 = 100% YES I1 ⇒ {I2,I5} 2/6 = 33% no I2 ⇒ {I1,I5} 2/7 = 29% no I5 ⇒ {I1,I2} 2/2 = 100% YES

Strong rules: {I1,I5} ⇒ I2, {I2,I5} ⇒ I1, I5 ⇒ {I1,I2}.

Shortcut: if a rule fails, every rule from the same itemset with a smaller left side also fails (a smaller subset has a count at least as large, so the confidence can only drop). Here {I1,I2} ⇒ I5 fails at 50%, so I1 ⇒ … and I2 ⇒ … fail without checking.

Which itemsets? If the question gives one itemset, use it. If it asks for all rules, do every frequent itemset of size 2 or more, not only the largest.

If the question says an item must be on the left or right (for example “A must be on the left and B on the right”, as in your 17/09 note), keep only the rules that satisfy that; other items can be on either side.

Han et al., §6.2.2 “Generating Association Rules from Frequent Itemsets”, Example 6.4. Notes: 17/09/26, 24/09/26.

6. Exam checklist and common mistakes

Layout to write in the exam
  1. Convert the threshold to a count (for example 40% of 5 transactions = 2) and state it.
  2. Write C₁ (v1), C₁ (v2), L₁ with the deletion reason (“count < threshold”).
  3. For each k ≥ 2: Ck (v1) the joined list; the theorem check with a reason for each removed candidate; Ck (v2) with counts; Lk.
  4. Stop when Ck or Lk is empty, and say why.
  5. State the final answer: all frequent itemsets from every Lk.
  6. If asked for rules: every subset, the confidence calculation, and the strong rules.

Common mistakes

  • Keeping items with count below the threshold. Keep count ≥ threshold, delete the rest.
  • Counting candidates that the theorem should have removed.
  • Counting an item twice because it is listed twice in one transaction.
  • Joining sets that do not share the first k−2 items, or joining two sets that are not both in Lk−1.
  • Mixing up support (divide by the total) and confidence (divide by the left side).
  • Forgetting that Apriori gives itemsets, and rules are a separate step.
